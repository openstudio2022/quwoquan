# 登录入口无死循环

所有登录入口必须同时满足**两个目标**。只满足一个就会产生死循环或断流。

## 双目标契约

- **关闭 / 稍后登录** → 回到不会再次触发登录门的安全状态。
  强入口必须 `allowGuestDismissPop: false`。
- **登录成功** → 进入用户刚才想去的目标状态，或经 `AuthContinuation` 续接原动作。

[MUST NOT] 只传 `dismissFallback` 却允许 `pop` 回触发点。
那会形成「关闭登录页 → 回到受限状态 → 再次弹登录」的死循环。

## 入口分型

- 首页关注频道等**内部 tab** 不能只靠路由表达目标，必须用明确 continuation 区分
  「关闭回首页/推荐」与「登录后进入关注」。
- `createEntry`、底栏加号、Web 创作主入口是**添加入口**：游客先看到动作面板或创建工作台，
  只有写文章、发图、发视频、草稿、加好友、群聊、建圈这些**具体动作**才触发登录。
- `/create?...` 真实创作页、消息、我的、评论、收藏、关注与私信、加入圈子等**账号态入口**
  仍需登录，并必须显式声明关闭安全态与成功目标态。

## MUST

gate: `make verify-app-login-entry-loop-contract`

新增或改动登录入口时同步补测试，两条都要：

- 关闭后再 pump，不再弹登录。
- 登录成功进入目标态，或完成 continuation。
