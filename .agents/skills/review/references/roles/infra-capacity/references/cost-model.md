# 容量与成本估算方法

承接原 `/infra-bench` 与 `/infra-plan` 中**经得起时间的部分**：估算方法、对比维度与
分层策略。原命令里的「当前实现快照」和具体报价**已全部删除**——快照多处与代码不符
（见 `../ROLE.md` 末尾），报价会随厂商调价失效。

**本页不含任何「我们现在是什么」的结论。** 需要现状时读代码或跑巡检。

## 估算容量：先算量，再谈钱

行为事件量级：

```
日事件数 = DAU × 人均 session 数 × 每 session 事件数
日字节数 = 日事件数 × 单事件字节数
月存储量 = 日字节数 × 30 × (1 - 压缩率)
```

媒体量级：

```
图片月增 = 日发布内容数 × 每条图片数 × 单图字节数 × 30
视频月增 = 日发布视频数 × 单视频字节数 × 30
CDN 月流量 = 月 PV × 每 PV 媒体数 × 单媒体字节数 × (1 - 边缘命中率)
```

缓存内存：

```
HotPath = 活跃用户数 × 单用户状态字节数
读缓存 = 热内容条数 × 单条字节数
会话   = 并发数 × 单会话字节数
```

先把这些数算出来再讨论选型。**没有量级的选型讨论一律打回。**

## 规模阶段

判断适用方案前先定位阶段，不同阶段的最优解不同：

| 阶段 | DAU | 内容量 |
|---|---|---|
| startup | < 1 万 | < 10 万条 |
| growth | 1–50 万 | 10–500 万条 |
| scale | > 50 万 | > 500 万条 |

## 埋点存储选型的对比维度

不要只比单价。逐项对比：

- **写入 QPS 天花板** 是否高于行为事件峰值。
- **多维分析查询延迟**：按 surfaceId × 实验桶 × 内容类型 × 来源切分时的表现。
- **保留成本曲线**：30d / 90d / 365d / 永久 各自的月成本。
- **冷热分层自动化程度**：需要自己搬数据还是引擎托管。
- **运维复杂度**：是否引入新的有状态组件与新的故障模式。

候选族（按运维复杂度递增）：托管列存、对象存储 + 查询引擎、通用文档库、
分布式 HTAP、自建流 + 对象存储。**具体产品与报价现场重新调研**。

## 分层保留策略

这套分层与厂商无关，是行为数据的通用形态：

```
热   实时推荐回流      内存 KV
温   近期指标与查询    在线库 + TTL
冷   历史分析与训练    对象存储列式格式（按天分区）
归档 合规保留          对象存储归档层
```

每层必须定义：驻留时长、迁出触发条件、查询入口、删除或归档的合规依据。
**缺任一项即视为生命周期未定义**，对应 design 阶段的 D2。

## 性能目标

这些是体验目标，不随厂商变化，可直接用作 SLO 输入：

| 指标 | 目标 |
|---|---|
| 推荐首屏 P99 | < 200 ms |
| 图片首字节 P95 | < 100 ms（CDN 命中） |
| 视频起播 P95 | < 500 ms |
| Feed 翻页 FPS | >= 55 |
| 端到端 行为 → 推荐 | < 30 s |
| 边缘缓存命中率 | > 95% |

判定时要求给出**实测值**。填 `?` 或「未知」等同于未达标，
应转 `OPEN-###` 并写明需要哪次压测补齐。

## 成本优化的常见杠杆

按 ROI 从高到低，仅作检查清单，不预设结论：

1. **CDN 媒体变换**（按需尺寸 + 现代格式）通常是带宽账单降幅最大的一项。
2. **冷热分层**把长尾数据移出在线库。
3. **压缩与去重**（gzip 上行、内容 hash 去重）。
4. **缓存层级**（进程内 L1 + 集中式 L2）降低回源。
5. **保留期收敛**——先问「这份数据留 365 天的业务依据是什么」。
