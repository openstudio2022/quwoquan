# ux · prd · base

prd 就要定的界面事项——这些留到 dev 再定，返工成本最高。

## PRE 准入

- [MUST] 页面四态（加载 / 空 / 错误 / 权限）在需求里都有说明，不只有成功态
  check: 只描述了有数据时的样子，判失败
- [SHOULD] 已确认复用现有组件还是新建；新建需说明为何现有组件不适用
- [SHOULD] 响应式预期已说明：窄屏与宽屏分别是什么形态
- [SHOULD] 文案已列出并可进 i18n，不是「到时候再写」
- [MAY] 已提供交互稿或参考页面

## DURING 执行中

- [MUST NOT] 规划平台私有的产品流程。IA、`route_id`、`surface_id`、主任务流、
  空态/错误态/权限态与文案 key 必须跨平台一致；差异只允许在布局密度、
  导航壳形态、内容列数与悬停/快捷键等增强上
  check: 逐条对比各平台的流程描述；出现某平台独有的步骤或独有的文案 key，判失败

## POST 自检

- [SHOULD] 新增页面已在页面对象契约中登记
  gate: make verify-app-page-object-contract

## HANDOFF 交接

- 产出：四态描述、复用决定、响应式形态、文案清单
- 未决项去向：未定的交互转 `OPEN-###`，不要用「按现有风格」搪塞
- 下一步：`design`，其 PRE 需要本次的四态描述
- 证据链：需求文档中的对应段落
