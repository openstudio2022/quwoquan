# 阶段契约：1.download

本阶段才把 source plan 物化为 source units、source refs 与媒体 CAS holdings。

## PRE

AI 在 OPEN 只提交并冻结逐 target source plans、下载/CAS policy 与对象 refs 的 exact refs。

## DURING

AI 逐 target 选择一个显式 candidate；candidate 原样携带 AI 决定的 `sourceUseMode`。随后按适用形态调用当前真实原子 I/O：

```bash
python3 quwoquan_data/scripts/cli.py task materialize-source \
  --candidate <candidate.json> --execution-id <id> --target-ref <ref>
```

人工文件可追加 `--manual-root`；图片/视频先分别使用只接受显式 manifest 的 `task acquire-images` / `task acquire-videos`，再由 `materialize-source` 绑定 acquisition receipt/CAS。命令每次只物化一个 source unit 与对象 `1.download/source_refs.json`，不得替 AI 选择候选、语义清洗、质量判断或 rights 结论。

AI 随后直接写 `source.clean.md`、`source.layout.json`、`source.quality.json`。video 同时绑定视频与 poster 的真实 source/CAS refs。失败时记录 typed issue，不伪造 holdings、不回退计划外来源。

## POST

机械 verifier：

```bash
python3 quwoquan_data/scripts/cli.py verify stage-artifacts --execution-id <id> --through 1.download
```

AI self-check：每个 source unit 是否对应 OPEN 中的 source plan/candidate，clean/layout/quality 是否忠实于原始 snapshot，媒体 bytes/identity/rights 线索是否可追溯。`verify source-digest` 是仓级 source identity 审计，不得冒充 execution 阶段证据。

## HANDOFF

- receipt ref/digest；
- `resultRefs`：source units、source refs、download manifests、CAS/media disposition exact refs/digests；
- `typedIssues`；
- Skill 固定后继：`2.quality`。
