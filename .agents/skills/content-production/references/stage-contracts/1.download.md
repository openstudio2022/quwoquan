# 阶段契约：1.download

本阶段才把 source plan 物化为 source units、source refs 与媒体 CAS holdings。

## PRE

- `sources` CLOSE 为 pass。
- AI 在 OPEN 显式冻结逐 target source plans、下载/CAS policy 与对象 refs。

## DURING

AI 逐 target 选择一个显式 candidate；candidate 必须原样携带 source plan 中由 AI 决定的 `sourceUseMode`，脚本不得根据 `sourceClass`、`purpose` 或权利线索推导。随后调用：

```bash
python3 quwoquan_data/scripts/cli.py task materialize-source \
  --candidate <candidate.json> --execution-id <id> --target-ref <ref>
```

人工文件追加 `--manual-root`；图片/视频先分别用仅接受显式 manifest 的 `task acquire-images` / `task acquire-videos`，再让 `materialize-source` 以 `--acquisition-receipt --receipt-asset-id --acquisition-root` 绑定 receipt/CAS。命令每次只物化一个 source unit：原始 `snapshot.raw|snapshot.bin`、`meta.json`、`source.md`、`assets/index.json`，并在锁内更新该对象 `1.download/source_refs.json`。所有网络仅 HTTPS，不接受访问控制绕过。

AI 随后直接写 `source.clean.md`、`source.layout.json`、`source.quality.json`；脚本不做语义清洗、布局推断、质量评审、候选排序或自动 repair。

homepage/image 的媒体处置与预算硬事实使用现有窄命令；video 同时冻结视频与 poster 的真实 source/CAS refs。下载失败、访问受限、摘要不符或预算不可满足时记录 typed issue，不伪造 holdings，不回退计划外来源。

## POST

逐条运行适用 verifier：

```bash
python3 quwoquan_data/scripts/cli.py verify stage-artifacts --execution-id <id> --through 1.download
```

AI 只提交真实 verifier facts，并决定 pass/blocked。`verify source-digest` 是无参 repo/release source identity 审计，不是 execution 下载阶段 verifier；需要仓级审计时可独立运行 `python3 quwoquan_data/scripts/cli.py verify source-digest`，不得把结果冒充本 execution 的阶段证据。

## HANDOFF

- `resultRefs`：source units、source refs、download manifests、CAS/media disposition refs。
- pass 后由 Skill 固定进入 `2.quality`。
