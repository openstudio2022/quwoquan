# 阶段契约：1.download

把来源引用的媒体字节确定性下载进 CAS，并为每个对象落 `1.download` 产物。

## 身份

- stage：`1.download`（与磁盘目录一字不差）
- 前置阶段：`sources`
- 合法 next：`2.quality`
- 角色人设：宿主 agent（确定性 CLI 调用，无独立人设）
- 写目录 allowlist：对象级 `1.download/`；媒体 CAS 只经下载 CLI 写入

## 做前（PRE）

- `sources` receipt `verdict=pass`；复跑：

```bash
python3 quwoquan_data/scripts/cli.py verify source-digest --execution-id <id>
```

## 做中（DURING）

- 图片 lane 唯一 CLI：`python3 quwoquan_data/scripts/cli.py task acquire-images …`；
  视频 lane 唯一 CLI：`python3 quwoquan_data/scripts/cli.py task acquire-videos …`。
  对象级 `1.download/` 产物清单真相源：`stage_artifact_contract.py`。
- homepage lane 的图片字节随来源单元在 `sources` 就位，本阶段的交付动作是逐图处置
  收口——全部来源单元就位后对整个 execution 跑一次：

```bash
python3 quwoquan_data/scripts/cli.py task freeze-homepage-media --execution-id <id>
```

  写入 create-once：重跑同一结论幂等，结论不同即以退出码 2 拒绝。
- [MUST NOT] agent 手写二进制、绕过 CAS 或直接拷贝文件进工作包。
- [MUST NOT] 下载失败时伪造 holdings 引用。

## 做后（POST）

交付件：下载清单 + 媒体 holdings 引用。完成判据**按 lane 绑定，不得任选**：

```bash
# homepage / image / video lane
python3 quwoquan_data/scripts/cli.py verify homepage-media-decision --execution <id>
# article lane
python3 quwoquan_data/scripts/cli.py verify stage-artifacts --execution-id <id> --through 1.download
```

判据只判「决策闭合」——每张下载图恰有一个合法处置，发布处置已冻结 `assetId`，非发布
处置不指向任何资产（[`DEC-029`](../../../../../specs/feature-tree/discovery-content/object-homepage-coverage-scaling/design.md#dec-029)）。
manifest 是否忠实兑现这些处置由物化后的 `verify homepage-media-fulfillment` 对账，
本阶段不判、也判不了。

字节预算同样在本阶段闭合：留下的每个资产都必须装进其载体的对象存储预算，因此通过本
阶段的资产不会在 publish 期因单资产字节预算被拒。预算数值只有一处声明——
`quwoquan_data/control_plane/_shared/media_processing.policy.yaml` 的
`objectStorageBudgetBytesByCarrier`，本阶段与 publish 门读同一处，禁止在下载侧另立
常量或另设更宽的放行值（[`REQ-012`](../../../../../specs/feature-tree/discovery-content/object-homepage-coverage-scaling/multi-carrier-release/spec.md#req-012)）。
超预算候选先按已声明交付档自宽到窄降采样，取第一个装进预算的档并按新字节身份重登记；
每档都装不进就在本阶段判否。`sourceAssetMaxBytes` 只是抓取传输上限，不是准入判据——
源体允许大于预算，因为降采样得先拿到源体。

常见 issue → 修复：

- 单 URL 下载失败 → 回 `sources` 为该目标换源（记入 openItems），不重试伪造。
- CAS 引用悬空 → 重跑对应下载 CLI 重建引用，不手改 JSON。
- 下载图无处置 → 处置未在本阶段冻结；跑 `task freeze-homepage-media` 让它落盘，
  不手写 JSON 补齐。
- `DATA.MEDIA.ASSET_OVER_BUDGET` → 该资产每档降采样后仍装不进载体预算，下一步是
  回 `sources` 换素材（记入 openItems）。不要调宽预算：预算是发布侧的存储与交付事实，
  调它等于让所有对象一起变贵。
- 来源单元 `researchLane` 缺席或不在 `homepage/article/image/video` 闭集内 →
  本阶段拿不到载体因而拿不到预算，直接判否。回 `sources` 补齐该单元的 lane 声明，
  不要在下载侧给它挑一个默认载体。
- 资产宽高看起来被转置（横图记成竖图）→ 该图的 EXIF Orientation 声明了 90° 旋转。
  本阶段记录的是交付端呈现的几何，出现转置说明读到了未经方向修正的旧产物；
  重跑本阶段让它按显示几何重登记，不手改 `assets/index.json`。

按 [handoff-protocol.md](../handoff-protocol.md) 落 receipt。

## 交接（HANDOFF）

- 失败 URL 进 `openItems`（`return_to_stage` → `sources`，或配额仍满足时
  `out_of_scope`）。
- `next=2.quality`。
