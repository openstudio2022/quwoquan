# 阶段契约：5.review

本阶段由与作者不同的一个真实 reviewer actor 会话负责同一 execution 的全部对象；不得由脚本合成结果，也不得建立对象级 actor projection。不同 execution 可由宿主原生并行。

## PRE

reviewer 在 OPEN 只提交并冻结逐对象唯一 carrier draft、sequence-006 receipt、sources/quality/compose refs、媒体与 rights evidence 的 exact refs。receipt 必须可读出该 execution 的真实 author actor/invocation、自检与 prompt/compose/draft digests；不得要求 draft meta/self-check/envelope 镜像文件。

## DURING

reviewer 的真实 session/runId 必须与 sequence-006 author 不同；同一 model family 可合法出现，不得伪造或用仓内 SDK/provider 回退。独立 reviewer 对每对象只写一份 `content_review.json`，统一包含：

- `decision=approved|rejected`；
- 简短 `dimensions` 与 `blockingIssues`；
- 对每个资产的 source/license/terms/authorization/usageScope 与 rights 结论；text-only 对象显式表达无资产适用项。

先判证据充分性，再判输入/policy 失配，最后判创作问题。review 不修改 draft；脚本、固定模板或聚合器不得生成 review、rights 结论或 approved 对象。不得再写 `rubric_review.json`、`reviewer_result.json`、`media_ref_review.json`、`attestation.json` 或独立 review receipt。

## POST

机械 verifier：

```bash
python3 quwoquan_data/scripts/cli.py verify stage-artifacts --execution-id <id> --through 5.review
```

AI self-check：每份 `content_review.json` 是否绑定对应 draft/source/media exact identity，rights 是否逐资产闭合，`approved|rejected` 是否有简短充分理由；sequence-007 receipt 的 actor/invocation 是否就是该 execution 唯一真实 reviewer，且与 sequence-006 author 的 session/runId 不同。approved 与 rejected 可并存，shortfall 写 stage result artifact/typed issue，通用 receipt 不新增 `partial`；至少一个 approved 且无 stage-wide identity/integrity failure 时可 `pass`，零 approved 或 stage-wide failure 才 `blocked`。verifier 通过不等于自动 approved。

## HANDOFF

- receipt ref/digest；
- `resultRefs`：逐对象唯一 `content_review.json` exact refs/digests；sequence-007 receipt 同时冻结真实 reviewer actor/invocation；
- `typedIssues`：含 rejected/shortfall 或 stage-wide blockers；
- Skill 固定后继：`publish`，其输入只包含 reviewer 明确 approved 的对象。
