# 阶段契约：5.review

本阶段由与作者会话独立的宿主 AI 逐对象评审；不得由脚本合成结果。reviewer session 的派发、并发与限流属于宿主 runtime，不写仓内调度状态。

## PRE

AI 在 OPEN 只提交并冻结逐对象 draft、draft meta、self-check、agent envelope、sources/quality/compose refs、媒体与 rights evidence 的 exact refs。

## DURING

reviewer 必须是独立宿主会话，真实 `sessionId`/actor/runId 与 `4.draft` 作者不同；同一实际 model family 可合法出现，不得伪造或用仓内 SDK/provider 回退。独立 AI 逐对象写：

- `rubric_review.json`：逐条判定与理由；
- `reviewer_result.json`：真实 reviewer actor/invocation；
- `media_ref_review.json`：唯一 media/rights authority，逐资产绑定 source/license/terms/authorization/usageScope/passed/issues；
- `attestation.json`：该对象唯一 `approved|rejected` 结论与 exact object identity。

先判证据充分性，再判输入/policy 失配，最后判创作问题。review 不修改 draft；脚本、固定模板或聚合器不得生成 rubric、rights 结论、approved 对象或 attestation。

## POST

机械 verifier：

```bash
python3 quwoquan_data/scripts/cli.py verify stage-artifacts --execution-id <id> --through 5.review
```

AI self-check：每份 review 是否绑定对应 draft/source/media exact identity，reviewer 是否独立，rights 是否逐资产闭合，`approved|rejected` 是否有充分理由。approved 与 rejected 可并存；无 approved 对象则 blocked。verifier 通过不等于自动 approved；最终 verdict 与 typed issues 由 reviewer AI 显式提交。

## HANDOFF

- receipt ref/digest；
- `resultRefs`：逐对象 rubric、reviewer result、唯一 media/rights review、attestation exact refs/digests；
- `typedIssues`；
- Skill 固定后继：`publish`，其输入只包含 AI 明确 approved 的对象。
