# 阶段契约：2.quality

逐素材保留/淘汰判定 + 事实抽取。

## 身份

- stage：`2.quality`（与磁盘目录一字不差）
- 前置阶段：`1.download`
- 合法 next：`3.compose`
- 角色人设：[quality-reviewer](../roles/quality-reviewer.md)（此处做素材质检，独立评审在 `5.review`）
- 写目录 allowlist：对象级 `2.quality/`

## 做前（PRE）

- `1.download` receipt `verdict=pass`；复跑其判据命令（按本 execution 的 lane
  取 [1.download.md](1.download.md) POST 栏对应那条，完整 argv 同栏）。

## 做中（DURING）

- 逐素材做保留/淘汰判定并把理由落盘到对象级 `2.quality/quality_analysis.json`
  （schema：`quwoquan_data/schema/content/quality_analysis.schema.json`）。
- 事实抽取必须记录来源锚点（哪个来源单元的哪个位置支持该事实）。
- [MUST NOT] 保留无来源锚点的事实；[MUST NOT] 淘汰后再引用被淘汰素材。

## 做后（POST）

交付件：每对象 `2.quality/quality_analysis.json`（保留集 + 事实底稿）。完成判据：

```bash
python3 quwoquan_data/scripts/cli.py verify stage-artifacts --execution-id <id> --through 2.quality
```

常见 issue → 修复：

- quality_analysis schema 校验失败 → 按报错字段修 JSON 结构。
- 保留量不足写作需求 → `openItems` 登记 `return_to_stage` → `sources`
  （计入 sources 的补源轮次）。

按 [handoff-protocol.md](../handoff-protocol.md) 落 receipt。

## 交接（HANDOFF）

- 保留量达标 → `next=3.compose`。
- 不足 → `verdict=blocked` + `return_to_stage:sources`。
