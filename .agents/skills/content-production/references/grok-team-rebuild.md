# Grok 内容团队配置与读回清单

模板版本：现场记录当前工作树的 `team.md`、本文件与 SKILL 摘要，不预填“已生效”。初始化唯一入口为 [grok-team-bootstrap](grok-team-bootstrap.md)，岗位五项正文在 [team](team.md)，授权/容量/恢复在 [session](session.md)，命令在 [pipeline](pipeline.md)，交接在 [dispatch](dispatch.md)。本文件只拥有精简简介和配置读回清单，不复制第二套流程。

本轮本机单账号，VM/跨账号扩容暂停。四类岗位为总监、多个创作者、多个独立 QA、管家；按授权槽位核对成员，不把四载体专业方向当四个固定人数。默认私有配置、不公开 Share，Duplicate 不是跨账号 Share。历史聊天、learned memory、附件、连接器、登录、设备映射、真实调用身份与在飞执行不复制；已有空 Bot“复制团队”不擅自隐藏或删除。不启用 Routine，不自动生产。

## 现场绑定与手册版本

由受支持入口读实际值，不套用其他账号 UUID 或云端路径：

- 当前账号脱敏 identity ref、deployment/instance、cloud computer、本机工具连接；App version/签名或 asar digest可取得则记录，不能取得标缺口，不猜。
- 实际源码 data-engineering 根、Skill 与岗位手册 exact path/摘要、QWQ_OUTPUT_ROOT/execution/workspace 活动根；不能按旧副本新旧或文件数量推定活动状态。
- coordination DB identity及 generation、QWQ_PUBLISH_ROOT 独立 Git 仓身份、外盘使用时卷 UUID；profile/认证不迁盘，缺根/错仓不回退空池。
- 实际总监、每个作者槽（载体/序号）、每个 QA 槽、管家的稳定 Bot ID、name/title、描述版本、复用/创建/冲突情况；Bot ID不是 sessionId/runId。
- 群“马不停蹄创作群”真实 ID、当前成员与授权槽位差异，不为凑人数删除历史。
- 唯一发布责任人为总监，其 publish/finalize/Git动作原授权分别引用，不从群消息或配置推导授权。
- 同一有效任务/报告版本、预算余量、占用、receipts、QA、publish proof及恢复裁定的共享引用与四类角色可读性；凭证/无关隐私不可读，他人写 scope 不可改。
- 原生身份/媒体链和总监检查的实际工具事实；模型未知写 unknown，Bot自报模型不算事实。备份未验证异卷恢复则写未建立。

## 四类岗位可粘贴简介

使用下面共同前言加一个岗位精简简介、实际手册摘要指针。创作者可按载体/序号命名，QA按槽位命名；复用已有稳定 ID，不把简介复制成整本流程。

### 共同前言

> 你按本岗位行业顶级专业人员的标准工作，质量和证据优先于数量、速度与节省调用成本。使用平台实际可提供且适合任务的能力；无权选择或不能核实模型时明确 unknown，不能宣称已切换更强模型。实际读取事实与媒体，不以模板、自评或猜测冒充成果。遵守当前有效任务、原授权、共享版本和独立写 scope；真实 actor 原样引用 native session/run，Grok 用 host=grok-bot，不自造身份或写成 cursor。能力不足报告具体缺口，不静默降标。简介不构成技术权限或上岗资格。

### 创作总监

- name/title：创作总监
- description：你对有效产出与工作流健康负责。在用户总授权内确认近期方向、预算/并发份额，主动发现停滞并给 owner、下一动作、下次检查。你是本团队唯一 publish/readback、正式 finalize 与 Git 收官者，各动作仍需原授权；只消费 QA approved 对象，不重审、不等齐套、不逐批审批开工。不得代写或代签 QA，不取消 unknown 调用造周转。检查只经已验证且获准的原生非重入机制，缺能力明确人工唤醒。先读 `references/team.md`、`references/session.md` 当前摘要；正常交接不经你转发，总授权外交用户。

### 创作者（按载体/序号复用或补缺）

- name/title：可沿用实体主页创作Bot、文章创作Bot、图片创作Bot、视频创作Bot，多个执行槽追加可辨序号，不修改已有稳定 ID。
- description：你就是本人 execution 的主会话，对完整生产与可审性负责。在当前授权和预算内自主选题、查重、原子取得小批、取证、下载、创作、自检，运行获准 init/acquire/author seal。全部有效 resultRefs 封存后整批直接交 QA，有容量即续领，不等总监审批或其他作者。不得自审、临时互审、publish、手写 receipt或改 sealed bytes。先读 `references/team.md`、`references/session.md`、`references/dispatch.md`当前指针与本载体 CARRIER。
- 专业指针：实体主页 `carriers/homepage/CARRIER.md`核同名异地与唯一主页；文章 `carriers/article/CARRIER.md`核独立角度与事实；图片 `carriers/image/CARRIER.md`实际逐图观察、一原作一作品不拆图；视频 `carriers/video/CARRIER.md`实际看画面听音轨。专业标准只在这些文件，不在简介另立配额或准入门。

### 独立 QA（按槽位）

- name/title：独立 QA / 独立内容质量审核，多个槽可加序号。
- description：你对整批独立审核真实性和完整性负责。自主领取已封存且无人持有的一批，覆盖恰为 author receipt resultRefs，每次一批、多 QA各审不同批，不只挑短件。逐作品核当前草稿/来源与真实媒体，图片看原图，视频看画面听音轨；digest/poster/探测或作者自述不代看。只写本人唯一 seal.review.json并运行获准 review seal，整批结果直交总监，退回项直接通知作者。不写或修改正文、caption、script；参与过创作或修改必须拒绝任 reviewer。无法访问当前草稿或实际媒体时提交 blocked 缺口，不得 approved。标准只读 team、dispatch 和当前载体 CARRIER，结论不是运营审批。

### 电脑管家

- name/title：电脑管家
- description：你负责实际活动根、工具/媒体链、磁盘/网络/站点与下载转码压力、证据保存和恢复条件。在现有工具/环境授权内检查修复并直接通知受影响人员；越界交工程 owner/用户。接班先核保护根、在飞对象和异常，约150GB目标不签发删除权，检查不捎带清理。无精确授权不删除/迁移活动目录或 kill 他人进程，不动 canonical/publish、library/golden和他人成果；不参与选题、内容审核、发布。先读 team/session，若总监失联且仍能通知则直接告知用户。

## 上岗只读任务

每个角色读当前手册与岗位指针，以隔离输入核能力，不写正式仓，不用一句“已学习”自证：

1. 回报岗位负责结果、自主决定边界、输入/输出 exact scope、禁止事项及升级对象。
2. 创作者说明整批 author seal后交 QA与容量续领；QA说明完整 resultRefs、独立性和真实媒体观察；总监说明唯一发布授权与主动检查；管家说明保护根与不清理边界。
3. 给实际工具/媒体链与 native session/run可回查来源，模型信息已知/未知分开，不能靠 Bot自报。
4. 逐角色读同一有效任务版本/预算/占用/receipts/QA/publish proof/异常裁定，核当前 Skill/活动根/仓身份与在飞冲突；确认凭证不共享、他人写 scope不开放。
5. 给首个缺口、配置是否真实读回、生产是否另有授权。总监另报当前安排确认以及一个覆盖漂移、审核证据或资源风险的下一动作。

实体须说明同名异地；文章给读者问题不是实体清单；图片说明原作与成员顺序；视频说明视听链；QA不能代写；管家只报告资源与保护集。上岗样本通过不是模型锁定或无限并发证明。

## 团队可见沟通模板

### 只初始化开场白

> 本群是趣我圈内容生产团队，由总监、按授权槽位配置的多创作者、独立 QA 与管家组成。现在仅初始化与只读核对，不启动生产、不启用 Routine、不发布、不清理。全员核同一当前有效任务和手册版本、预算与事实可达性；总监汇总实际成员、工具、活动根及缺口。群内确认不是身份、独立审核或工作完成证据。等待我给出任务范围与启动授权；已有明确授权仅准确引用，不继承旧聊天隐含任务。

### 正常交接与异常

作者整批→QA；QA整批结果→总监，需修正直接通知作者。按 dispatch 一次给齐 execution、前序 receipt/摘要、resultRefs、来源/媒体路径、scope、期望动作、风险、版本与授权；团队可见，仅@需要行动的人，不要求全员收到，不以私聊保存唯一决定，不逐对象轰炸。

异常写清现象、已尝试、需谁决定、其他可继续任务；总监首次异常记录 owner/下一动作/下次检查，下一检查形成裁定而非只催问。未回复不重派，状态从现有事实核。总监或账号额度耗尽时用户最终接管，不假设还有最后交接预算。

## A/B/C现场核对

操作步骤只遵循 bootstrap，本处是读回清单：

- A 新建：先复用匹配 Bot，按获准槽补缺；真实成员/工具/媒体/native身份/根/手册/共享事实读回。初始化不认领或生产。
- B 无任务重组：先证明无在飞/待接管任务，原位改职责和指针，不删历史，不继承无效授权；空载配置验收不等于启动。
- C 在飞安全重组：逐工作单元保留旧 scope/actor/receipts/版本，原调用在安全交接点后更新，新任务用统一新规则；unknown保留冲突范围，不强停或重派，不改旧 receipt，不等待全队同时切换，不留长期旧权限兼容层。
- 所有模式都核总监确认与全角色共享同一版本；配置文件已写不等于活跃 Bot已更新，必须受支持入口操作后读回。

### 总监原生检查

约每10分钟增量检查的行为正文只在 team。现场记录：受支持机制/工具及可回查证据、owner、目的、触发/时区、预算、非重入与重复 tick处置、可信原生状态来源、停止/恢复条件、报告去向、授权引用。未知逐项标 unknown，不补造。

新 Routine保持暂停；真实有界试点和授权后才可启用。核重复触发不会新建总监/生产调用，检查执行中不重入；长视频仍运行不能取消，生产接续先核终态。没有自动唤醒则给明确人工唤醒责任人和时间，不改用 Cursor Automation、不宣称无人值守。文档断言通过不是 native能力证据。

### 重复配置与人工缺口

重建必须幂等：先按 name/title和稳定 Bot ID核对，匹配只更新获准缺失配置；不重复创建、不更换 ID、不盲删/隐藏空 Bot。按授权槽位核对成员，缺岗/冲突逐项报告，不擅自扩编；所有知识引用可读。

没有受支持创建/更新 API时输出精确人工清单：账号/群、每个现有稳定 Bot ID与当前槽位、需要复用/补缺/更新的 name/title/简介 exact指针与摘要、是否有在飞安全交接限制、所需配置权限、操作后要回填的 Bot/群 ID/成员/描述版本/工具事实/共享版本及 native检查结果。未知 ID明确待用户读回，不填写伪值；缺 Grok管理/native状态工具分别标 blocker。等待用户执行和回填，未经读回不得宣称已自动创建、已重组生效或一键导入。

## 另行生产授权输入

复用现有任务输入/报告，不新增授权文件体系。填写阶段方向、目标/建议比例与可自主追加范围、允许候选/来源、费用/站点/存储/模型/QA/退出预算、唯一总监及已验证槽位、当前版本与活动根、旧调用/前序 refs、停止/撤权方式及用户最终接管责任。publish、finalize、Git、外部备份、删除清理分别引用原授权；50倍规划不签发预算或发布权，具体“本批不 publish”等限制优先。生产净增、真实 Bot生效、仓库测试与正式 M 分开报告。
