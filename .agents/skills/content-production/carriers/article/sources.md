# Article 来源

只读当前实际来源小节。所有第三方正文只取事实，模板/筛选/评分只在 [CARRIER](CARRIER.md)。这些模块只取得显式一页，不自动检索选题或翻页。

## wikipedia · 已实现

来源名 `wikipedia`，request `{"title":"<条目名>"}`；取得 zh.wikipedia 正文、结构化 wikitext、revision 与消歧信息，输出本 article 目录的候选和 source.md，支持原始 API JSON 离线回放。可用实体条目或主题条目，但宿主决定独立角度与事实关联，不把百科长文直接改标题发布。

许可、作者等缺项由宿主根据实际页面补充 selection；脚本不自动宣布 CC、核实实体或生成可发布文章。

## toutiao_baike · 已实现

来源名 `toutiao_baike`，request `{"title":"<条目名>"}`；取公开页的 `__prefetch_doc_data__`，保留正文/信息区及版本（有则），离线 response 为 HTML。无正文或结构化块即停止，不绕过挑战页。

同名人物、异地地点要由 AI 排除。用于百科缺口或主题事实，不宣称实现头图取得，也不按站点统一补许可。

## reference_page · 已实现

- 来源名 `reference_page`，request 必须带 `{"url":"https://<公开页>","title":"<已核实标题>"}`；请求显式 URL，机械去脚本/样式提取可见 HTML 文本，输出候选与 source.md；离线 response 为原始 HTML。
- 可用于携程游记、公开景区/政府/文旅公告与新闻页面。它不是携程专用解析器，也不自动验证正文、作者、发布日期或页面是否软广；宿主需排除导航壳、无事实正文与过时内容。
- 候选不自动填许可/creator/accessPolicy；依据原网页补真实事实。页面标题由 request 传入，不把它误当脚本已核实的事实。

## 发现与补充 · 宿主工具

- 携程：检索 `site:you.ctrip.com/travels <实体> 游记 OR 攻略`，目的地列表可按热度/最新找候选；没有作者主页批量采集模块，不承诺作者页可达。落定公开 URL 后才交 reference_page。
- 官方/新闻：景区官网、文旅/政府公告、新华网与中新网等优先补门票、开放、交通、节庆；须看发布日期及适用条件，不按域名默认“最新正确”。
- 磨房、zh.wikivoyage、其它公开旅行页由宿主确认可达与使用方式后取事实；视频标题或携程标签只能启发角度，不证明正文事实。没有专用模块就不冒充已实现自动化。
