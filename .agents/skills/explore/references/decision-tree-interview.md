# 决策树访谈（decision-tree-interview）

把「用户没说清」消灭在最便宜的阶段的可复用交互原语。owner 是 `explore`；
`prd`、`plan-next` 需要时引用本文件，不复制正文。

## 何时使用

- 意图含糊、存在多个待裁决分叉，或验收/范围无法冻结时。
- 不适用：事实能从仓库、文档或工具查到时——**事实是你的工作，不是用户的**。

## 机制

1. 把全部待定事项映射为**决策树**：每个决定分叉出依赖它的后续决定。
2. 按**轮**工作。frontier = 前置条件均已确定、现在就能问而不用猜的全部问题。
   一轮把整个 frontier 问完：每题编号并给出你的推荐答案，然后等用户回答。
3. 问题格式：

   ```text
   ❓ Q<N> - <标题>：<问题正文，可含多选项>
   ➡️ <你的推荐答案>
   ```

4. 用户每轮回答会重塑树：已定决策把 frontier 向外推进。重算 frontier 再问下一轮。
   答案依赖本轮仍未定问题的，属于**后面的轮**，本轮不问。
5. **事实与决策分离**：frontier 问题需要环境事实（文件系统、工具、代码）时，
   自己查或派子代理查，不阻塞其余 frontier；只有下游依赖该事实的问题等结果。
   **决策**必须交给用户并等待回答。
6. 终态：frontier 为空——决策树每个分支都已走到、没有默默假设的残留。
   用户确认达成共识前，不得进入下一工作流。

## 禁止

- 一次抛出开放式「你想要什么」；每题必须带推荐答案。
- 把能查到的事实抛给用户。
- frontier 未清空就宣布共识达成。
