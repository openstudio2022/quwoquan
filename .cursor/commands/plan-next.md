# /plan-next

目标：完成一轮开发后，先对整个计划做闭环复核与自检，再基于节点 OPEN、棘轮残量与新用户价值生成下一轮会话计划。

## 闭环复核（五段，顺序执行）

1. **计划对账**：读取当前会话计划（`.cursor/plans/*.plan.md` 或会话 todos），逐条对照真实产物（git diff、门禁输出、测试结果）判定：
   `完成有证据 / 完成但证据弱 / 部分完成（写明范围裁剪理由与残量）/ 未完成`。
   判据是达成意图而非做了动作；证据必须指向具体命令输出或测试结果。
2. **并行任务归因**：用 `git status` 区分本计划改动与并行会话改动；执行中每个失败/红灯强制归因四选一：
   `本计划引入 / 并行会话中间态 / 存量债 / 环境 flaky`。
   归因必须有基线对照证据（HEAD 版本重跑、`git log --follow`、文件归属、复跑），禁止无证据断言"与我无关"；列出双向交接项（本计划替并行收尾的、需并行会话收口的）。
3. **环境与门禁健康**：重跑影响面门禁确认归零（如 `make verify-feature-tree` 与受影响 verify 脚本）；检查环境不可用或长期阻塞信号——`stackctl health/verify` 证据、连续多轮红且无 owner 的门禁、凭证/网络/容器依赖缺失；每项区分"本轮可修"与"登记 OPEN"。
4. **缺口与风险裁决**：执行中发现的冲突、技术债务与风险逐项三选一裁决：
   `当前增量直接修复 / 写入最低 owner 节点 OPEN（完成判定必须引用验收锚点）/ 明确 Out of Scope 并说明理由`。
   受影响棘轮基线（ceiling 类门禁）逐个列出当前值与收敛方向，只减不增。禁止中央风险台账、changelog 或成熟度矩阵。
5. **闭环判定**：按批次列完成项与证据、未完成项与缺口、初始风险与现状的逐条对照（消减/转移/残留）、剩余阻断；判定：
   `闭环 / 带残量闭环（棘轮与 OPEN 承接）/ GATE_BLOCK`。

## 生成下一轮计划

1. 已解决事项删除 OPEN 并成为当前规格；未完成事项放在最低 owner 节点 OPEN，不能用下一轮计划遮盖。
2. 运行 `make feature-tree-overview` 和 `make feature-tree-change-report` 获取风险/规划总览与本轮影响。
3. 下一轮计划写在当前会话，包含目标、规格增量、实施任务、验收锚点、测试层、质量门与退出条件，任务清单明确可验收；不创建 tracked tasks、plan 或 changelog。

本轮仍有无证据完成声明、测试失败未归因、未归属变更或 `OPEN block` 未处置时返回 `GATE_BLOCK`，不得宣称已进入下一轮开发。

自然语言等价触发："下一轮做什么""完成后再规划""计划复核""闭环自检""这轮做完了吗"。
