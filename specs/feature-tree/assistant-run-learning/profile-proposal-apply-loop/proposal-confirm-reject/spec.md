# L3 Story：提案确认拒绝 (`proposal-confirm-reject`)

> 所属能力：[`profile-proposal-apply-loop`](../spec.md)

> Journey / Scenario：[`JNY-007 / SCN-015`](../../../spec.md#scn-015)

> 设计归属：[L2 DEC-001](../design.md#dec-001)

## 1. 用户价值

作为使用小趣的用户或助手运营者，
我希望状态流转必须幂等，不允许非法跳转，
从而获得可解释、可恢复且可持续改进的助手结果。

## 2. 范围与非目标

### In Scope

- “提案确认拒绝”的输入、可观察主路径、失败语义以及与父能力的交接。

### Out of Scope

- 父能力中由其他 Story 独立拥有的行为、能力级架构决定和实现任务。

## 3. 行为要求

<a id="req-001"></a>
### REQ-001 提案确认拒绝

- “提案确认拒绝”必须通过父能力公开契约交付可观察结果；失败时返回 canonical failure，不写入成功事实。

<a id="req-002"></a>
### REQ-002 状态流转必须幂等，不允许非法跳转

- 状态流转必须幂等，不允许非法跳转。

<a id="req-003"></a>
### REQ-003 禁止跨状态跳转；重复操作必须幂等

- 禁止跨状态跳转；重复操作必须幂等。

## 4. 契约引用

- 父能力公开契约：[`L2 spec`](../spec.md)。

## 5. 验收场景

<a id="gwt-001"></a>
### GWT-001 提案确认拒绝

- GIVEN 使用小趣的用户或助手运营者具备有效身份，且父能力声明的输入与上游事实成立。
- WHEN 参与者执行“提案确认拒绝”对应的公开行为。
- THEN 通过父能力公开契约交付“提案确认拒绝”的可观察结果。
- AND 失败时返回 canonical failure，且不产生伪成功事实。
