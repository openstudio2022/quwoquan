# L3 特性：video-display-journey（视频旅程）

## 功能说明

**视频独立旅程**：视频频道 / 首页混合流 → 视频未播放封面 → 视频沉浸式浏览器 → 作者详情，端到端数据源一致、交互状态跨页面同步、重入状态保持。与图片旅程模式一致，按 category=video 隔离。

- **数据源**：列表、浏览器、作者详情共用同一 feed（category=video）
- **展示**：未播放态展示 `thumbnailUrl`，缺失时只允许回退同源 `coverUrl`；浏览器展示与 post 一致（作者、关注、赞、收藏、评论数、转发、视频、文字）
- **状态**：关注/赞/收藏跨页面同步；作者详情关注变更返回后同步；退出再进状态保持
- **滑动**：左右滑动顺序与视频频道 feed 一致；滑动到底加载更多

## 适用范围与约束

- **适用**：发现页首页混合流、视频频道、通用视频卡、作品浏览器、视频沉浸式浏览器（ImmersiveVideoViewer）、作者详情
- **约束**：须支持 Mock/Remote 一键切换；按 category=video 隔离，不与图片混用；不得把 `videoUrl` 当图片 URL 交给 image loader

## 视频封面展示合同

- 视频未播放态的唯一展示来源为服务或数据工程生产出的 `thumbnailUrl`；`thumbnailUrl` 缺失时只允许回退到与同一视频 post 或同一 media asset 同源的 `coverUrl`。
- 首页、通用视频卡、作品浏览器、沉浸式浏览器首帧态必须消费同一封面优先级，不允许使用无关 seed 图、作者头像、地点图、视频 URL 或端侧运行时临时抽帧。
- 播放初始化成功后，UI 可从封面切换到真实视频画面；播放失败时保留同源封面并展示结构化错误/恢复动作。
- 数据工程导入视频与用户上传视频使用同一展示合同，不能通过入口差异维护第二套封面字段。
- 封面展示、点击播放、错误恢复和停留/互动行为必须具备 `referralSource` / `feedRequestId` / trace 传递，支撑推荐与运营分析。

## 验收

- A1：列表、浏览器、作者详情数据与 post 一致
- A2：关注/赞/收藏跨页面一致，重入后保持
- A3：作者详情关注/取消后返回，浏览器展示更新
- A4：滑动顺序与列表一致，支持加载更多
- A5：视频旅程能力与图片一致
- A6：Mock/Remote 切换后正确
- A7：首页、通用视频卡、作品浏览器未播放态展示 `thumbnailUrl` / 同源 `coverUrl`，点击后进入真实视频播放。
- A8：数据工程导入视频与用户上传视频在 feed/read model 中使用同一封面展示合同。
