# L2 Design：媒体处理与辅助阅读 (`media-processing-helper-read`)

> 对应规格：[L2 spec](./spec.md)

> 设计触发原因：“图片/视频从上传完成事实到 ready/rejected 终态、归一化公开切片与可预览读取的商用闭环”需要 `helper-read-summary`、`image-delivery-variants`、`media-failure-recovery`、`media-status-pipeline` 共享状态 owner、契约或质量边界。

## 1. 背景、目标与非目标

- 设计目标：图片/视频从上传完成事实到 ready/rejected 终态、归一化公开切片与可预览读取的商用闭环。
- 设计目标：Data 发布侧的图片体以 CDN 四档即时变换的输入身份进入 immutable release，体量约束以单对象存储预算在对象闭包上构成准入而不是事后报告。
- 非目标：复制字段 schema、实现任务、测试排列组合或执行历史。
- 非目标：归一化衍生体的格式、重编码质量、EXIF/ICC 去留与源体摘要落点，四项由 Story 开放事项的受治理 calibration 承接。
- 非目标：单对象存储预算的逐载体数值及其门禁实现，本能力只消费该预算不认领它。

## 2. Story 协作与状态流

- [`helper-read-summary`](./helper-read-summary/spec.md)：定义“辅助读取摘要”的可观察主路径、失败语义及父能力交接。
- [`image-delivery-variants`](./image-delivery-variants/spec.md)：损坏、超限、descriptor 缺字段或 CDN baseline 不可读全部进入 rejected 或保持 processing 重试，不能发布。
- [`media-failure-recovery`](./media-failure-recovery/spec.md)：checkpoint 保存失败后重放同一事实只产生一个有效 ready 结果。
- [`media-status-pipeline`](./media-status-pipeline/spec.md)：带音轨与无音轨输入均产生 H.264/AAC progressive fast-start MP4。

## 3. 端云与数据流

- 上游能力：[`discovery-content`](../spec.md) 声明的领域入口。
- 下游能力：本目录直接 Story 及其公开结果。
- 一致性要求：遵循本层或父 L1 DEC 声明的一致性边界。
- 交付端能力差异：不具备即时变换能力的交付端对四档返回同一存储体字节，该差异由环境拓扑的能力声明表达，不由 descriptor 或 profile 承载。

## 4. 关键决策

<a id="dec-001"></a>
### DEC-001 media_not_ready 只在处理完成后解除
- 决策：media_not_ready 只在处理完成后解除。
- 理由：图片/视频从上传完成事实到 ready/rejected 终态、归一化公开切片与可预览读取的商用闭环。
- 被否决方案：由调用方、页面或脚本复制本层状态并绕过公开契约。
- 约束与影响：实现只能细化对应规格与 canonical contract；冲突时先修正规格或契约。
- 关联要求：`REQ-001`
- 影响 Story：[`helper-read-summary`](./helper-read-summary/spec.md)、[`image-delivery-variants`](./image-delivery-variants/spec.md)、[`media-failure-recovery`](./media-failure-recovery/spec.md)、[`media-status-pipeline`](./media-status-pipeline/spec.md)
- 关联验收：`SIT-001`

<a id="dec-002"></a>
### DEC-002 发布侧逐资产准入只判可解码性，最宽 profile 封顶与长边判据一并退役
- 决策：Data 发布侧的逐资产准入收敛为一条判据，即存储体能否被真实解码探测；`quwoquan_data/scripts/core/media_normalization.py` 承载的最宽 profile 宽度封顶与长边判据整体退役，不保留开关、可调阈值或 warn-only 轨。
- 决策：该模块的规格归属由本能力认领。在本决定之前它不属于任何节点，因此任何人都能改动它而不触发任何准出。
- 决策：该层交出 typed 终态而不是可空问题串。可解码是在场结论，探测失败与解码能力缺失都是失败结论，两者不得共用「返回空即通过」这一个载体。
- 理由：四档声明的宽度是交付输出宽度。要让最宽档交付到它声明的宽度，存储体至少得有那么宽；用输出宽度反推存储输入上限只会让最宽档永远拿不到声明宽度。
- 理由：长边与交付宽度不同轴。按长边归一化会把一张宽度本就低于最宽档的竖构图继续压低，等于让一个与判据无关的轴决定交付质量。
- 被否决方案：把判据从长边改成宽度但保留封顶——因果方向未变，仍然是拿输出反推输入上限。
- 被否决方案：给封顶加开关或调高阈值——两个取值并存即双轨，且任何取值都缺乏实测依据。
- 被否决方案：让该层继续返回可空问题串、只在调用处包一层 typed 外壳——失败仍由字符串是否为空表达，解码能力缺失与「没有问题」在载体上无法区分。
- 约束与影响：通过权利与质量准入的源体字节原样成为存储体，发布侧不做格式转换、重编码或 EXIF/ICC 改写，存储体摘要因此就是源体摘要。
- 约束与影响：源体宽度低于最宽档声明宽度时原样入库不放大，放大只增加字节不增加信息。
- 约束与影响：图片质量准入拥有的像素下限与本决定不同轴也不同时点，`quwoquan_data/scripts/core/image_asset_strategy.py` 的下限判定不随本决定变化。
- 约束与影响：资产级失败必须传导为对象级终态，被正文引用时对象整体 blocked，未被引用时形成 typed exclusion 且对象继续。
- 可观察面：local_contract 以真实编解码的最小图片体分别构造宽度高于最宽档、宽度低于最宽档但长边高于它、以及不可解码三种输入，断言前两者被接受且存储体与源体逐字节相同，第三者得到 typed 失败。锁定旧封顶与长边规则的既有断言随本决定退役，不与新断言并存。
- 关联要求：`REQ-003`
- 影响 Story：[`image-delivery-variants`](./image-delivery-variants/spec.md) 的发布侧存储基线面
- 关联验收：`GWT-006.t1`、`GWT-006.t2`、`GWT-006.t3`、`GWT-006.t4`

<a id="dec-003"></a>
### DEC-003 一致性判据绑 profile 参数，有效交付宽度由单点取小投影派生
- 决策：四档声明宽度是上界而不是保证。任一档的有效交付宽度只由「声明宽度与存储体宽度取较小者」这一个投影派生，三侧不各自计算像素结果。
- 决策：一致性判据绑在 profile 参数上。三侧解析同一 descriptor 得到相同参数即为一致，某档实际交付宽度小于声明宽度不构成 descriptor、profile 或三侧解析不一致。
- 理由：存储体不再设封顶之后，宽度低于某档声明宽度的存储体是常态。把一致性判据绑在像素结果上会把这类合格存储体判为违约，而它们恰恰是不放大这条决定的直接产物。
- 理由：投影只有一个来源时，交付端能力差异只改变该投影的输入，不需要在每个消费点重复裁决谁优先。
- 被否决方案：存储体宽度不足时放大到声明宽度——它改写存储体字节，使摘要与源体分离，权利快照绑定的摘要随之与发布体对不上。
- 被否决方案：让三侧各自比较像素结果——同一 descriptor 在三侧得出三个结论，一致性判据自己成为第二真相源。
- 约束与影响：`quwoquan_service/services/content-service/contracts/media/media_asset/image_variant_policy.yaml` 仍是四档参数的唯一来源，本决定不改变任一档的声明宽度。
- 约束与影响：不具备即时变换能力的交付端对四档返回同一存储体字节，这是该投影输入的一个取值，不是违约。
- 可观察面：local_contract 用宽度分别高于与低于最宽档声明宽度的两个存储体解析最宽档，断言有效交付宽度分别为声明宽度与存储体实际宽度，且两者都不产出不一致结论。
- 关联要求：`REQ-003`
- 影响 Story：[`image-delivery-variants`](./image-delivery-variants/spec.md) 的四档解析一致性面
- 关联验收：`GWT-006.t5`、`GWT-006.t6`

<a id="dec-004"></a>
### DEC-004 体量准入绑在对象闭包封缄那一步，度量与预算数值仍单点归既有门禁
- 决策：单对象存储预算的准入判定发生在对象事务把闭包封缄成 `objectClosureDigest` 的那一步，由 `quwoquan_data/scripts/content/release/canonical/object_transaction_contract.py` 提供的同一个封缄边界执行。post 与 entity 两个载体的事务构建器都只能经该边界封缄，不得各自判定。
- 决策：对象闭包的成形以 `objectClosureDigest` 覆盖的字节集合为准。进入该摘要的文档与被引用媒体体全部进入预算度量，不进入该摘要的一律不进入。
- 决策：度量口径与逐载体预算数值仍由 `quwoquan_data/scripts/verify/verify_object_size_budget.py` 单点拥有。准入对单个对象根调用它求值，既有门禁继续做全量事后扫描，两者共用同一函数与同一预算表。
- 理由：单写者只有绑在两个载体共用的封缄边界上才是结构性的。绑在各自构建器里靠约定调用时，新增载体漏调用不会被任何东西发现。
- 理由：把成形定义成一个已经存在且必须计算的摘要，使该时点可被验证，而不是一句需要人工遵守的约定。
- 理由：度量方式与预算数值只有一份实现时，准入与门禁不可能给出不同结论；复制一份就等于承认两者可以漂移。
- 被否决方案：在逐资产层加体量封顶——逐资产孤立判定看不见闭包总量，回答不了「这个对象能不能发」。
- 被否决方案：只保留既有门禁的事后全量扫描——canonical 对象已经写定，它只能报告既成事实，不能阻止对象进入 release。
- 被否决方案：把判定推到 immutable release build——对象那时已进统一池，超预算只能表现为选择时被排除，池里会长期躺着永远发不出去的对象。
- 被否决方案：在准入侧另写一份闭包度量——两份实现就是两套体量口径，也让预算数值出现第二个落点。
- 约束与影响：准入失败时事务不产出对象事务包，暂存目录整体丢弃，因此不存在已写入再回滚的中间态。
- 约束与影响：同一媒体体在一个对象内被引用多次只计一次，物理重复不为该对象购买额外额度。
- 约束与影响：单对象存储预算本身的规格 owner 仍然缺失，缺口留在 Story 的开放事项里，本能力不代为认领。
- 可观察面：local_contract 构造预算内、闭包累计超出与单资产自身超出三个对象走同一封缄边界，断言只有第一个产出对象事务包，并断言两个载体的构建器都无法绕过该边界完成封缄。
- 关联要求：`REQ-003`
- 影响 Story：[`image-delivery-variants`](./image-delivery-variants/spec.md) 的对象级体量准入面
- 关联验收：`GWT-007.t1`、`GWT-007.t2`、`GWT-007.t6`

<a id="dec-005"></a>
### DEC-005 超预算是整对象 blocked，两个成因各自成码并直接写进对象级排除面
- 决策：对象闭包超出预算的处置是整对象 blocked。发布侧不逐资产裁剪、不丢弃正文已引用的图、不生成降级衍生体。
- 决策：闭包累计超出与单资产自身即超出是两个互不合并的 typed 码，由准入判定处直接产出，并原样写入 publish 阶段 lane 回执的对象级排除条目。
- 决策：这两个码不经由异常消息二次匹配得到，`quwoquan_data/scripts/content/release/canonical/object_transaction_contract.py` 的 typed 判定不通过字符串匹配派生它们。
- 理由：丢弃正文已引用的图会在正文里留下悬挂引用，illustrated 对象的封面与正文图闭包同时破裂，得到的是一个既不完整也没有失败记录的对象。
- 理由：两个成因指向两个运营动作，累计超出指向减少该对象引用的资产数，单资产超出指向换掉这一张。合并成同一个 blocked 会让运营者拿不到可执行的下一步。
- 理由：从异常消息反推码等于在闭集之外藏一张转换表，改一句错误文案就能悄悄改变运营者读到的原因。
- 被否决方案：把超预算资产做成 typed exclusion 让对象继续——正文引用随即悬挂，且它把一个对象级判定伪装成资产级判定。
- 被否决方案：在发布侧生成降级衍生体把对象压回预算内——衍生体的格式与重编码质量尚未冻结，落地只能靠默认常量。
- 被否决方案：为超预算另建终态台账——publish 阶段 lane 回执的对象级排除面已经承载「哪个对象没发出去、为什么」，第二份记录只会成为可漂移的第二真相源。
- 约束与影响：超预算对象计入 publish 阶段的对象级排除，既有恒等式「已 finalize 对象数加被排除对象数等于 review 合格对象数」继续成立。
- 约束与影响：对象级 blocked 只终结该对象，批次终态沿用 [`multi-carrier-release`](../object-homepage-coverage-scaling/multi-carrier-release/spec.md) 的合格对象数语义，介于零与 quota 之间为 partial。
- 约束与影响：进程退出码、stdout 文本与运行日志都不是本终态的呈现面。
- 可观察面：local_contract 对两种成因各构造一个对象，断言两者得到不同的码且都落在对象级排除条目内；api_integration 在一次真实 execution 的 publish 阶段证明超预算对象被排除时同批合格对象仍进入 release。
- 关联要求：`REQ-003`
- 影响 Story：[`image-delivery-variants`](./image-delivery-variants/spec.md) 的超预算处置面
- 关联验收：`GWT-007.t2`、`GWT-007.t3`、`GWT-007.t4`、`GWT-007.t5`、`GWT-007.t6`

<a id="dec-006"></a>
### DEC-006 交付端即时变换能力是显式声明，取证缺口由该声明持续暴露
- 决策：交付端是否具备即时变换能力是环境拓扑里的一条显式声明，由环境巡检读取并输出，不靠人工记忆维持。
- 决策：声明为具备变换能力的交付端必须给出真实交付宽度的 api_integration 证据；声明为不具备的交付端只证明四档返回同一存储体字节，其交付半段显式记为本能力未证明。
- 决策：四环境目前全部声明为不具备该能力，因此「真实变换端按有效宽度交付」这一半不由本能力证明，缺口留在 Story 的开放事项里，不得由投影断言冒充已成立。
- 理由：取证缺口写成散文会随时间失效，写成一条被巡检读取的声明之后，任一环境接入具备变换能力的交付端时证据要求自动生效。
- 理由：「无法证明会变换」与「已证明不变换」是两个结论，后者是可取证的能力差异事实，前者是缺口。让同一条声明同时驱动两者，二者就不会互相冒充。
- 被否决方案：用测试替身模拟具备变换能力的交付端来覆盖该半段——它证明的是替身按投影返回，不是任何真实交付端按宽度交付。
- 被否决方案：对公网 CDN 取证——不受治理且不可复现，还会把本能力的准出绑到第三方可用性上。
- 被否决方案：为取证临时给某个环境加装变换器——证据来自一个不会发布的拓扑，取证结束即失效。
- 约束与影响：环境证据入口统一 `quwoquan_ops/cli/stackctl.py`，本决定不新增第二个环境查询入口。
- 约束与影响：该声明只描述交付端能力，不进入 descriptor、profile 或存储体字节，因此翻转它不改变任何已冻结 release 的内容。
- 可观察面：api_integration 在真实对象存储上断言四档返回同一存储体字节；环境巡检输出该声明的取值与其证据状态，取值翻转为具备能力而交付宽度证据缺失时 GATE_BLOCK。
- 关联要求：`REQ-003`
- 影响 Story：[`image-delivery-variants`](./image-delivery-variants/spec.md) 的交付端取证面
- 关联验收：`GWT-006.t5` 的交付半段与 `GWT-006.t6`

## 5. 失败与恢复

- 失败类型：权限拒绝、依赖超时、版本冲突或持久化失败。
- 可见结果：调用方收到可区分的 canonical failure 或规格明确允许的降级结果；任何失败均不写入成功事实。
- 恢复动作：调用方按 canonical recovery action 重试、刷新或停止；不得自行合成成功结果。
- 禁止 fallback：不得回退到 Mock、旧 wire、双读双写或页面本地写副本。
- 存储体不可解码：该资产得到 typed 失败终态，被正文引用时对象整体 blocked，未被引用时形成 typed exclusion 且对象继续；两种情况都不得在对象内留下悬挂引用。
- 对象闭包超预算：整对象 blocked 并按成因写入两个互不合并的码之一，运营动作分别是减少该对象引用的资产数与换掉超出预算的那一张。
- 同批隔离：对象级 blocked 只终结该对象，同批其他合格对象继续物化进 release，批次终态按合格对象数收敛。
- 体量准入不设 bypass：关闭它等于让「发布前判定」退化为 warn-only，预算调整只能落在既有门禁单点拥有的数值表上。

## 6. 质量与观测

- 缺少 `eventId` 或 checkpoint 的 source cursor 不可安全跳过，Worker 必须 fail-closed 并保持 checkpoint 不推进。
- 体量准入按 execution 观测被拦下的对象数、两个成因各自的计数与被拦对象的闭包字节分布；这些是准入事实，不参与 quota 与 milestone 判定。
- 观测值只作为下一次预算评估的输入，不得回写为预算数值，也不得据此为单个对象放宽准入。
- 交付端变换能力按环境观测该声明的取值与其证据状态，取值翻转即触发对应环境的交付宽度证据要求。
