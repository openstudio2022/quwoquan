# L3 Story：拍摄信息披露 (`capture-metadata-disclosure`)

> 所属能力：[`publish-comment-reaction`](../spec.md)

> Journey / Scenario：[`JNY-003 / SCN-008`](../../../spec.md#scn-008)

> 设计归属：[L1 DEC-001](../../design.md#dec-001)

## 1. 用户价值

作为发布照片的作者，
我希望自己决定公开哪几类拍摄信息（器材、参数、地点、时间），关掉的那类就彻底不出现在任何地方，
从而既能让懂的人看懂我怎么拍的，又不会把家门口的坐标顺手交出去。

## 2. 范围与非目标

### In Scope

- 素材自带拍摄信息的读取、归属与敏感字段处理。
- 发布时按分组做出的披露决策及其归属。
- 由拍摄信息派生的标签的写入路径与撤回语义。

### Out of Scope

- 交集的识别与展示，由 `object-homepage-network` 负责；本节点只保证事实与其撤回。
- 标签体系本身的定义与发布，由内容标签能力负责。
- 图片编辑与导出，由 [`image-editing`](../image-editing/spec.md) 负责。

## 3. 行为要求

<a id="req-001"></a>
### REQ-001 拍摄信息归属素材，披露决策归属发布

- 拍摄信息必须归属到素材：一次发布可包含多张照片，各自带有独立的拍摄信息。
- 披露决策必须归属到发布：它是作者在发布这一刻做出的选择，不是素材的固有属性。

<a id="req-002"></a>
### REQ-002 位置与时间按敏感信息处理

- 坐标与拍摄时刻必须按敏感信息分类并在日志中脱敏；不得以明文进入日志或可被未授权方读取的投影。

<a id="req-003"></a>
### REQ-003 披露以分组为粒度

- 披露决策以器材、参数、地点、时间四个分组为粒度；作者可分别开关，不得只提供全开或全关。
- 该四分组是 canonical 闭集 `CaptureDisclosureGroup`，端云两侧同源：提交命令声明为
 `type: '[]enum'`，App 生成 `List<CaptureDisclosureGroup>` 并在解码期拒绝闭集外的值。
 草稿层为兼容历史记录仍按 wire 字符串读写并静默丢弃非法项，但该宽容不得越过提交边界。

<a id="req-004"></a>
### REQ-004 派生标签的写入不得破坏只读投影语义

- 由拍摄信息派生的标签必须经受控写入路径落库；不得把内容标签这一只读派生投影改写为可自由写入字段。

<a id="req-005"></a>
### REQ-005 关闭披露必须整棵子树撤回

- 关闭某个分组后，该分组派生的标签及依赖其成立的事实必须在服务端整棵子树撤回；端侧裁剪不构成撤回。
- 撤回后该分组的信息不得继续出现在任何展示、检索或推荐结果中。

<a id="req-006"></a>
### REQ-006 服务本地契约引用边界

- 跨边界字段、operation 与错误语义只引用所属服务 contracts；本节点不得复制 wire 定义。

<a id="req-007"></a>
### REQ-007 派生目标以时间与地点为主线，器材与参数只作不可见事实

- 拍摄信息的派生优先级由「大众旅行读者能否用得上」决定：`capturedAt` 派生季节与节气标签并预填到访时间，
 GPS 派生地点标签候选；这两类进入召回、排序与搜索筛选。
- 器材与参数派生的标签保留为可展示的拍摄事实，但不得进入搜索筛选与创作者打标候选：
 它们描述「怎么拍的」而非「拍到了什么」，受众面不足以支撑筛选维度。
- 光线条件（金色时刻、蓝调时刻等）按画面氛围而非器材归类，与画面主体标签同级消费。
- 转向不改变披露语义：`REQ-003` 的四个分组粒度与 `REQ-005` 的整棵撤回原样适用于新的派生目标。

## 5. 验收场景

<a id="gwt-001"></a>
### GWT-001 开启披露后拍摄事实成立

- GIVEN 作者选择了若干张带有完整拍摄信息的照片并开启全部披露分组。
- WHEN 作者完成发布。
- THEN 各素材的拍摄信息分别落到对应素材上，派生标签经受控路径写入并可被读取。
- AND 坐标与拍摄时刻按敏感信息处理且在日志中脱敏。

<a id="gwt-002"></a>
### GWT-002 关闭分组后整棵子树撤回

- GIVEN 一篇已发布且已开启地点披露的内容。
- WHEN 作者关闭地点披露分组。
- THEN 该分组派生的标签与依赖其成立的事实在服务端整棵撤回。
- AND 该分组信息不再出现在任何展示、检索或推荐结果中，且不残留于其他分组。

<a id="gwt-003"></a>
### GWT-003 派生落在季节与地点而非器材

- GIVEN 作者选择了一张带有拍摄时刻与坐标的照片并开启时间与地点披露。
- WHEN 作者完成发布。
- THEN 该内容获得由拍摄时刻派生的季节标签，且到访时间被预填；坐标产出地点标签候选。
- AND 器材与参数派生的标签不出现在搜索筛选维度与创作者打标候选中。

## 7. 开放事项

<a id="open-001"></a>
### OPEN-001 拍摄信息尚未到达服务端

- 类型：`capability_gap`
- 优先级：`P1`
- 准出影响：`block`
- 影响或价值：当前服务端没有拍摄信息与披露决策的契约，端侧读取管线也没有生产调用点——
 `extractMediaCaptureMetadata` 只在测试树被调用，`PublishSettings.captureMetadata` 恒为 `empty`，
 因此 `captureDerivedTagRefs` 恒为空列表，发布时那次合并永远是空集。派生标签两端都不成立，
 依赖到访时间与地点引用的交集类型也无法激活。断点由 `verify_tag_collection_wiring.py` 的 `UNWIRED_BASELINE` 固化。
- 完成判定：`GWT-001` 与 `GWT-002` 对应行为满足且真实测试 `spec_ref` 有效

<a id="open-003"></a>
### OPEN-003 派生目标仍指向器材参数，未转向季节与地点

- 类型：`capability_gap`
- 优先级：`P1`
- 准出影响：`block`
- 影响或价值：当前派生器把已解析的拍摄事实转成器材与参数标签，而 `capturedAt` 与坐标这两项对大众旅行读者
 更有价值的事实没有派生目标：季节标签拿不到、到访时间不预填、地点标签无候选。
 结果是唯一具备采集能力的通道服务于最小众的维度。
- 完成判定：`GWT-003` 的 4 条 THEN 组全部具备子句级 `spec_ref`（`gwt-003.t1..t4`）绑定的真实测试证据，且断言覆盖派生目标转向季节与地点维度。

<a id="open-002"></a>
### OPEN-002 关闭披露的服务端撤回尚未实现

- 类型：`capability_gap`
- 优先级：`P1`
- 准出影响：`block`
- 影响或价值：当前关闭披露只在端侧裁剪展示，服务端不撤回已派生的事实，关闭后信息仍可能经检索或推荐路径外泄。
- 完成判定：`GWT-002` 的 3 条 THEN 组全部具备子句级 `spec_ref`（`gwt-002.t1..t3`）绑定的真实测试证据，其中必须含服务端撤回已派生事实的断言，仅端侧裁剪展示不计闭合。
