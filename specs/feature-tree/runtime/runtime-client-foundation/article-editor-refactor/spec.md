# L3 Story：文章编辑器分页与排版 (`article-editor-refactor`)

> 所属能力：[`runtime-client-foundation`](../spec.md)

> Journey / Scenario：[`JNY-001 / SCN-004`](../../../spec.md#scn-004)

> 设计归属：[L2 DEC-001](../design.md#dec-001)

## 1. 用户价值

作为创作文章的用户，
我希望在块级编辑器中编排文字、标题、列表和图片，并让编辑与预览共用分页切片，
从而获得所见即所得且可恢复的长文创作体验。

## 2. 范围与非目标

### In Scope

- 文章编辑器的块级编辑、统一分页切片、图文环绕、可访问性和预览一致性。

### Out of Scope

- 父能力中由其他 Story 独立拥有的行为、能力级架构决定和实现任务。

## 3. 行为要求

<a id="req-001"></a>
### REQ-001 文章编辑器分页与排版

- 编辑动作不可用时必须置灰；可用时必须符合对比度与不小于 44pt 的触控热区。

<a id="req-002"></a>
### REQ-002 不可用时 置灰；可用时符合对比度与触控热区（≥44pt）

- 不可用时 **置灰**；可用时符合对比度与触控热区（≥44pt）。
- **行 3 — 文本层级**：**正文**、**小标题**、**大标题**；**单选**。面向用户**不得**暴露 `H1/H2/H3/H4` 术语，内部映射关系在 design 中冻结。
- 选图、裁剪与编辑跳转必须复用 canonical 图片编辑入口；环绕方式变更必须在编辑画布上立即反映。
- 每个 **逻辑块**（段落、标题、列表项、图文组合等）使用 **统一卡片表面**（圆角、边框/阴影语义、内边距 token）。
- **文档真相**：`ArticleDocumentData` 为唯一真相；**排版顺序**在文档流上连续计算（`ArticleFlowLayoutEngine`：`LayoutRun`/fragment 序列 + 测量高度），**禁止**将「横向预览页数」与「文内图张数」机械对齐。
- **统一分页切片**：编辑态与预览态必须共用 **同一 page metrics 与 page slice 结果**；编辑只是在这些 page slices 上提供输入能力，预览则只读展示。
- **页面边界**：若某元素（尤其通栏图）在当前页剩余高度内无法完整放置，则 **整块移到下一页**；编辑与预览页边界必须一致。
- **页宽 / 页高**：页宽与页高均由统一 page metrics 决定；编辑态不得使用与预览不同的“无限高轻量页”作为终态。
- **页面壳**：编辑态每一页都必须具备 **明确页框、页眉、页脚/页码与固定页范围**；其 **页宽/页高/内容区** 与预览态一致，仅允许弱化沉浸背景和阴影强度。
- **外框约束**：**禁止** 再给整列编辑区包一层粗外框；只保留 **单页纸张** 的细边框 + 轻阴影，形成“多页堆叠”质感。

## 5. 验收场景

<a id="gwt-001"></a>
### GWT-001 编辑与预览共用分页切片

- GIVEN 开发、测试或运维角色具备有效身份，且父能力声明的输入与上游事实成立。
- WHEN 用户编辑跨页文字、标题、列表和图文块并切换预览。
- THEN 编辑与预览使用同一 page metrics 和 page slice，块级边界一致；不可用动作置灰且可用动作触控热区不小于 44pt。
- AND 失败时返回 canonical failure，且不产生伪成功事实。
