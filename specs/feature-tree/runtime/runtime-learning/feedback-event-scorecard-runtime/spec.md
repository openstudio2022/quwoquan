# L3 Story：反馈事件评分卡运行时 (`feedback-event-scorecard-runtime`)

> 所属能力：[`runtime-learning`](../spec.md)

> Journey / Scenario：[`JNY-001 / SCN-004`](../../../spec.md#scn-004)

> 设计归属：[L1 DEC-001](../../design.md#dec-001)

## 1. 用户价值

作为维护助手学习链路的工程角色，
我希望把学习反馈规范化为可校验、可聚合且隐私受控的 scorecard，
从而让策略评估和反馈注入使用同一事实口径。

## 2. 范围与非目标

### In Scope

- “反馈事件评分卡运行时”的输入、可观察主路径、失败语义以及与父能力的交接。

### Out of Scope

- 父能力中由其他 Story 独立拥有的行为、能力级架构决定和实现任务。

## 3. 行为要求

<a id="req-001"></a>
### REQ-001 反馈事件评分卡运行时

- “反馈事件评分卡运行时”必须通过父能力公开契约交付可观察结果；失败时返回 canonical failure，不写入成功事实。

<a id="req-002"></a>
### REQ-002 与上层 runtime 契约一致，禁止服务内重复实现

- 与上层 runtime 契约一致，禁止服务内重复实现。

## 5. 验收场景

<a id="gwt-001"></a>
### GWT-001 反馈事件评分卡运行时

- GIVEN 开发、测试或运维角色具备有效身份，且父能力声明的输入与上游事实成立。
- WHEN 参与者执行“反馈事件评分卡运行时”对应的公开行为。
- THEN 通过父能力公开契约交付“反馈事件评分卡运行时”的可观察结果。
- AND 失败时返回 canonical failure，且不产生伪成功事实。

<a id="gwt-002"></a>
### GWT-002 事件版本幂等且评分卡投影可重建

- GIVEN 同一版本化反馈事件被重复投递或需要重放。
- WHEN 运行时计算 scorecard 并重建学习投影。
- THEN 重复事件不重复计分，重建结果与原投影一致且遵循隐私控制。
