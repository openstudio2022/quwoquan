# L3 Scenario: full-screen-search-shell-and-entry

## 节点定位

- `L1_domain_service`: `global-search-experience`
- `L2_business_capability`: `cross-domain-search-journey`
- `L3_story`: `full-screen-search-shell-and-entry`

## 背景与动机

全局搜索首先是一个壳层问题，而不是一个接口问题。最新需求已经把壳层形态从“单页搜索首页”收敛为“两段式体验”：初始态负责记录与管理，输入后切换为联想态。入口上下文和视觉结构必须随之统一，否则用户无法形成稳定心智。

## 目标用户

- 从首页、聊天、群组、助手页进入搜索的普通用户。
- 需要先看最近搜索、再通过实时联想快速直达结果的高频用户。

## 功能范围

- 统一全屏搜索首页初始态与输入后的联想态。
- 统一首页、聊天、群组、助手页的搜索入口行为。
- 搜索框、`最近在搜` 双列卡片、展开、垃圾桶进入记录管理态的壳层布局。
- 输入后的联想态中，严格按 `最常使用 / 联系人 / 聊天记录 / 搜索网络结果` 四段展示。
- 默认 placeholder、返回路径与上下文保留。

## Out of Scope

- 独立网络结果页的数据编排。
- 最近搜索的同步实现细节。
- 语音 ASR 识别实现细节。

## 约束

- 全局搜索必须是唯一全屏全局浮层。
- 页面视觉必须遵循 iOS 原生 UX 规则与 design token。
- 搜索入口不得在各页自行维护第二套 path、surface、route 行为。
- “更多联系人 / 更多聊天记录”只能在当前页内联展开，不得跳到新中间页。
- 搜索框尾部只保留清除按钮；输入框内部不得再表达请求进度。
- 同一搜索 request generation 只能有一个主进度；页面无结果时由正文承载，已有本地结果时仅“搜索网络结果”区块可承载局部进度。
- 本地联系人、会话、消息、常用项并行查找并在 1.5 秒内各自结算；聊天同步与圈子预热只能后台 best-effort，不能阻塞联想。
- 云端实体主页从请求开始即获得 6 秒总预算；3 秒只是阻塞空白页的慢提示，不得在 3 秒重新发请求或延长 deadline。
- query 变化、清空、返回与页面销毁必须取消 transport、递增 generation 并清理计时器；旧响应不得覆盖新 query。
- 发布态实体主页在既有“搜索网络结果”段直接预览；“钱”使用包含匹配命中“东钱湖”，不新增第五分段。

## 对标输入与吸收结论

- 以微信搜索首页的最近搜索与输入后联想切换作为直接对标。
- 吸收顶部搜索框、最近搜索、输入后实时联想分段结构。

## 角色分工

- `global-search-experience`: 负责壳层、入口、上下文与两段状态切换。
- `_shared` metadata: 负责 route、surface、page context 真相源。

## 既有 Story 覆盖矩阵

| 既有实现 | 处理 |
|---|---|
| `GlobalSearchSheet` 原型 | 被新壳层吸收并替换 |
| 各页面局部搜索图标行为 | 收口到统一入口策略 |

## 数据生命周期合同

- 本 Scenario 只关心展示“最近搜索”区块，不定义其持久化细节。
- 入口页上下文只在本次打开搜索期间保留，具体持久化不由本 Scenario 冻结。

## 小趣 / 权限 / 分享边界

- `小趣搜` 不在本 Scenario 作为快捷按钮出现，而是在独立网络结果页中处理。
- 本 Scenario 不新增分享能力。

## 非功能目标

- 搜索首页打开即时可见。
- 初始态与联想态在深色/浅色、不同断点下保持同一信息架构。
- 云读取首批结果目标仍为 1.5 秒；阻塞且无内容到 3 秒只播报一次慢提示，6 秒必须取消并进入可重试终态，禁止无限 pending。
- spinner、慢提示和终态满足 Semantics、深浅色与 reduced-motion；不得记录原始 query。

## 迁移、灰度与回滚要求

- 本 Scenario 不保留旧壳层并行路径。
- 若新壳层出现严重问题，整体回退到旧搜索实现。
- alpha、beta、gamma、prod 使用同一 App 代码与 1.5/3/6 常量；alpha full/lite fixture 包含“东钱湖”，beta 由延迟/取消/部分失败测试看护。gamma 需真实链路补证，prod 在 canonical `/search` 拓扑就绪前保持 `GATE_BLOCK`。

## 验收重点

1. 统一入口和统一全屏壳层成立。
2. 初始记录态与输入后联想态结构清晰稳定。
3. route / surface / page context 不再散落在各页面手写。
4. 输入框无 spinner，超时、空态、部分结果和失败严格区分，任何路径都能结束等待。
