# L2 Design：搜索 Provider 路由与存储拓扑 (`search-provider-routing-and-storage-topology`)

> 对应规格：[L2 spec](./spec.md)

> 设计触发原因：“统一搜索 contract、对象 taxonomy、Provider 路由、显式降级、本地搜索生命周期与云侧派生读模型，为全屏搜索和页面内 picker 提供同一查询边界”需要 `canonical-search-contract`、`circle-group-hybrid-fallback-contract`、`local-search-lifecycle-and-account-isolation`、`search-execution-routing-policy`、`search-object-taxonomy-and-provider-registry`、`search-risky-config-gray-release`、`search-storage-topology-and-elasticity` 共享状态 owner、契约或质量边界。

## 1. 背景、目标与非目标

- 设计目标：统一搜索 contract、对象 taxonomy、Provider 路由、显式降级、本地搜索生命周期与云侧派生读模型，为全屏搜索和页面内 picker 提供同一查询边界。
- 非目标：复制字段 schema、实现任务、测试排列组合或执行历史。

## 2. Story 协作与状态流

- [`canonical-search-contract`](./canonical-search-contract/spec.md)：页面与业务层只看到一个 contract，商用字段以 metadata 为唯一真相源。
- [`circle-group-hybrid-fallback-contract`](./circle-group-hybrid-fallback-contract/spec.md)：fallback 必须返回 typed `resolvedFrom=local_fallback`。
- [`local-search-lifecycle-and-account-isolation`](./local-search-lifecycle-and-account-isolation/spec.md)：定义“本地搜索生命周期与账号隔离”的可观察主路径、失败语义及父能力交接。
- [`search-execution-routing-policy`](./search-execution-routing-policy/spec.md)：定义“搜索执行路由策略”的可观察主路径、失败语义及父能力交接。
- [`search-object-taxonomy-and-provider-registry`](./search-object-taxonomy-and-provider-registry/spec.md)：location 成为 canonical search 可召回的一类对象，且 geo 维度机制仅一套。
- [`search-risky-config-gray-release`](./search-risky-config-gray-release/spec.md)：每个发布 revision 必须绑定兼容镜像范围和配置摘要；环境 overlay 不得包含真实 endpoint 密钥、password 或 token。
- [`search-storage-topology-and-elasticity`](./search-storage-topology-and-elasticity/spec.md)：搜索读请求只走 metadata 只读 API + 注入 CloudRequestHeaders 审计；多读切片按 objectType 独立弹性。

## 3. 端云与数据流

- 上游能力：[`global-search-experience`](../spec.md) 声明的领域入口。
- 下游能力：本目录直接 Story 及其公开结果。
- 一致性要求：遵循本层或父 L1 DEC 声明的一致性边界。

## 4. 关键决策

<a id="dec-001"></a>
### DEC-001 统一搜索 Contract 与 Planner，读模型实现可替换
- 决策：统一搜索 Contract 与 Planner，读模型实现可替换。
- 理由：统一搜索 contract、对象 taxonomy、Provider 路由、显式降级、本地搜索生命周期与云侧派生读模型，为全屏搜索和页面内 picker 提供同一查询边界。
- 被否决方案：由调用方、页面或脚本复制本层状态并绕过公开契约。
- 约束与影响：实现只能细化对应规格与 canonical contract；冲突时先修正规格或契约。
- 关联要求：`REQ-001`
- 影响 Story：[`canonical-search-contract`](./canonical-search-contract/spec.md)、[`circle-group-hybrid-fallback-contract`](./circle-group-hybrid-fallback-contract/spec.md)、[`local-search-lifecycle-and-account-isolation`](./local-search-lifecycle-and-account-isolation/spec.md)、[`search-execution-routing-policy`](./search-execution-routing-policy/spec.md)、[`search-object-taxonomy-and-provider-registry`](./search-object-taxonomy-and-provider-registry/spec.md)、[`search-risky-config-gray-release`](./search-risky-config-gray-release/spec.md)、[`search-storage-topology-and-elasticity`](./search-storage-topology-and-elasticity/spec.md)
- 关联验收：`SIT-001`

<a id="dec-002"></a>
### DEC-002 Elasticsearch 作为可替换 SearchIndexView Provider，以单代 Binding 与版本化投影保证一致性
- 决策：Elasticsearch 是当前生产搜索 Provider；替换不得降低现有中文 IK/pinyin、fuzzy/phrase、相关性排序、geo/vector、highlight、PIT 翻页快照与 alias 零停机 rebuild 能力。
- 边界：搜索核心 canonical contract、Planner 与 Provider Port 只表达查询、分页快照、投影写入/删除、重建与代际切换等语义操作，不暴露 Elasticsearch DSL、原始 PIT id、index/alias 细节或厂商响应；DSL、PIT 生命周期和 alias 操作只存在于 Provider Adapter 内。
- 对象与 owner：`SearchIndexView` 是可由领域事实重放或 backfill 重建的 projection，不成为业务写真相源；每个 searchable object 的 source owner 仍属于对应领域，Search 只拥有投影、查询与 Provider 适配。
- Deployment Binding：`search.objects` 是 reader 与全部 writer 共同消费的一个逻辑 deployment binding generation。每代一次性封存 endpoint、read/write alias generation 与按角色引用的 credential，由部署控制面原子激活并 fan-out；reader、writer、admin 分别使用不同的最小权限凭据，任一参与者观察到缺失或混合 generation 必须 fail-closed。
- 一致性与幂等：所有投影 sink 必须在 Provider 内以 source owner 提供的 `sourceVersion` 做原子条件写，拒绝旧版本 upsert；删除必须写入携带 source version 的 tombstone，任何不高于 tombstone version 的迟到或重放 upsert 都不得复活对象。同版本重放保持幂等，不得依赖到达顺序纠正结果。
- 当前文档单轨：公开搜索只读取 [SearchIndexDocument](../../../../quwoquan_service/services/search-service/contracts/search/search_index_view/projections/search_index_document.yaml) 的完整合法形状；旧文档缺必需字段、null、非法版本/摘要或未知来源必须在 Provider 查询前隐藏，不能等 reindex 回执才关闭兼容。普通 Post/User/Homepage/圈子/location 与 Data Creator/Post/Homepage 共享 current 门禁，来源与 release fence 叠加，覆盖 term/vector/ids/count/facet/PIT；普通 producer 的共同 mapper 必须同步显式写 ordinary，不能以“不是 Post”为查询豁免。字段与值域只归上述 contract。
- 历史恢复边界：保留旧 bytes 供离线审计，Provider `_id`/`_version` 与 sourceVersion/external version 的合法顺序继续保留；同版本异摘要拒绝，不改成成功或提高虚构版本。owner 只可按真实事实显式重投，无法跨过旧内部版本时在受管独立新索引重建并验证后整代切换；查询不得补字段、改旧 bytes 或连接环境自动迁移。旧候选/proof 不能重释为 current，需 owner 重新 prepare；无全对象闭包、真实查询证据与受管切换能力保持 not-ready。
- 当前形状测试 seam：以现役隔离 CJK ES 工具启动独立实例；正例通过生产 mapper/Indexer/VersionedWriter 构造，损坏恢复专项再逐个移除必需字段或置 null/非法版本/摘要，验证所有查询路径旧形状零可见、合法非 Post 不漏召回、ordinary/Data fence 与向量一致；保留 tombstone 防旧 upsert、同版本同摘要重放及异摘要冲突断言。原 legacy 测试改语义而非删除或改名避扫描；此处不声称测试或环境已通过。
- Checkpoint：Mongo 只保存每条投影流的 checkpoint/watermark，不与 Elasticsearch 组成分布式事务。Provider 文档或 tombstone 成功后才能推进 checkpoint；两者之间失败时保留旧 checkpoint 并安全重放，由 source-version 条件写吸收重复和乱序。
- Provider 替换：候选 Provider 必须先通过覆盖上述能力的 capability conformance 与 canonical Search SLO conformance，再经受控 projection rebuild、校验和整代 binding 原子切换完成 migration；禁止运行期 Provider fallback、按请求选择 Provider 或由调用方携带 selector。回滚只能恢复到仍满足 freshness/readiness 的上一已验证整代 binding，否则先重建并保持当前代，不能以请求级双路由掩盖失败。
- 拓扑不变量：Elasticsearch、search-service、indexer 与 Mongo 的物理共址或拆分只改变部署与容量，不改变 canonical contract、Planner 语义、source owner、`SearchIndexView` 一致性或 `search.objects` binding generation。
- 理由：当前 Elasticsearch 能力已经构成生产搜索行为基线；将实现细节封在 Adapter、将读写端绑定为同一代并以 source version 驱动 projection，才能在不污染领域 contract 的前提下支持可重建、可迁移和可证明不复活的数据路径。
- 被否决方案：在 contract 或 Planner 中透传 ES DSL/PIT；让 SearchIndexView 接管领域 source owner；reader 与各 writer 独立选择 endpoint/alias 或共用全权凭据；用 Mongo + Elasticsearch 分布式事务、到达顺序或无版本删除维持一致性；以运行期 fallback、请求级 selector、长期双读双写或物理拓扑差异替代受控 migration。
- 失败与恢复：capability/SLO 不满足、binding generation 不一致、凭据越权、投影条件写失败、checkpoint 落后、tombstone 冲突、重建校验失败或切换失败均产生可区分的 typed failure 并阻止成功事实或代际切换；恢复通过重放、backfill、整代重验与原子切换完成。
- 回滚与观测：切换前保留上一已验证 generation 的只读恢复材料；持续观测 canonical Search 延迟/错误率、projection freshness、旧版本拒绝数、tombstone 防复活冲突、checkpoint lag、binding generation skew、rebuild 校验与切换结果，阈值按 canonical Search SLO 告警并阻止迁移或触发整代回滚。
- 测试 seam：Provider conformance 覆盖 IK/pinyin、fuzzy/phrase、相关性、geo/vector、highlight、分页快照和 rebuild；静态 contract test 阻断 ES DSL/PIT 类型越过 Port；binding test 证明 reader/全部 writer/admin 同代且权限隔离；乱序 upsert/delete、重复投递及 Provider 成功但 checkpoint 未推进的故障注入证明旧写拒绝与 tombstone 防复活；migration test 证明 capability/SLO 准入、整代原子切换、整代回滚以及无运行期 selector；同一套 contract test 在共址与拆分拓扑下结果一致。
- 关联要求：`REQ-001`、`REQ-002`
- 影响 Story：[`canonical-search-contract`](./canonical-search-contract/spec.md)、[`search-execution-routing-policy`](./search-execution-routing-policy/spec.md)、[`search-object-taxonomy-and-provider-registry`](./search-object-taxonomy-and-provider-registry/spec.md)、[`search-risky-config-gray-release`](./search-risky-config-gray-release/spec.md)、[`search-storage-topology-and-elasticity`](./search-storage-topology-and-elasticity/spec.md)
- 关联验收：`SIT-001`

<a id="dec-003"></a>
### DEC-003 Search 候选准备流程拥有 checkpoint，Content 独占激活，IndexView 保持只读投影

- 决策与 owner：新增 Search-owned `SearchReleasePreparation`，按 [工程 DEC-023](../../runtime/system-architecture-and-engineering-guide/design.md#dec-023) 建模为 process_manager，独占候选准备 checkpoint、执行权与完成证明，不拥有 release activation/rollback 或 active pointer。它因 Provider 已提交但本地证明尚未提交时必须从 checkpoint 恢复而成立，不是为容纳 command 凭空创建业务 aggregate。SearchIndexView 继续为 projection/reader，只提供同域 typed 投影与候选查询 port，不声明 prepare HTTP command、不增加 runtime entrypoint；Provider 写入仍归 SearchIndexView 投影 adapter，流程只能调用 application port，不能导入兄弟 infrastructure 或直接写 ES。普通账户继续消费 `UserProfileSearchProjectionRequested`，不改变资格与安全投影。
- 公开来源与唯一 registration：`user.profile` 仍由 `user.user_account` 的既有公开资料契约边界唯一注册；在该 owner 增加受信 candidate 公开快照 query，经 User 同域 Creator application reader 读取 exact verified candidate，不创建账户或把 Creator 送入账户生命周期。现役 `PersonaService.GetPersonaProfileView` 已通过注入的 Creator reader 与 composition adapter 返回 Creator 资料，证明公开契约 owner 与资料事实 owner 可分离；新准备 query 必须显式读取目标候选，不能复用仅读 active fence 的公开 query。Creator 保留内部投影、不再次认领 object type；来源差异由 owner 的 typed 公开输入、UserProfile 原事件和独立准备 operation 表达，不新增多 owner registry。账户 eligibility 函数及事件原样保留，Creator eligibility 独立依赖 verified candidate 与公开字段，禁止 OR 入账户 active 判据；更新 registration 说明和该 owner 的搜索投影委托边界，但不假称现有账户 projector 已处理 Creator。公开身份冲突须在 User 公开投影边界和 Search 投影入口阻断，不能让现有先查 Persona 的行为掩盖碰撞。
- 跨服务快照：在现役 `quwoquan_service/contracts/metadata/_shared/types.yaml` 单写真正由 User、Content、Search 共同消费的 release binding 与 Creator 公开快照值，参照已有 `GreetingIntersectionSnapshot` 的 User 生产、Chat 消费方式；User 仍是值的事实 producer，共享声明只拥有 wire。各服务 request/response envelope 引用同一个值，不各自复制快照、使用裸 object、扩展 external 类型解析器或在共享层注册新对象。Content fence transport 本身仍引用 Content canonical contract，不在共享值中复制其请求/响应。
- 最小 command/query 裁决：Content 正式 release lifecycle 从 User 唯一公开 owner 的受信 candidate query 取得完整快照闭包，调用准备流程的受信 HTTP 推进命令，再 query 该流程的持久状态与就绪证明。最小为一个创建/显式续跑同一准备的 POST command 与一个只读状态/证明 query；路径、operation ID、scope 与 wire 在新对象 operations/fields/errors authoring，不在设计中猜 endpoint。按现役 MediaImageReprocessRun，application 用 command facet 与 `aggregate_owner` 指向 process_manager 自身，对象 access 使用 process_facade、version_source 使用 checkpoint，查询用独立 named Reader；不新增 schema 字段、不放开 projection command 或 HTTP/runtime 互斥。命令可在有界请求内推进，受理或中断不等于 ready；失败/响应丢失先 query 再显式恢复，无新增消息流、后台自动调度或第二推进轨道。
- 单主线升级：Creator/Post/Homepage只用一个SearchReleasePreparation typed prepare/query与proof，slice区分对象种类而非兼容版本。一份状态形状、一组checkpoint/receipt及一条consumer路径；删除旧Creator-only和额外typed-slice双入口、reader/writer及配置客户端测试分支。旧receipt仅离线审计，当前candidate重新prepare，不默认补字段、不重新解释旧completed。checkpoint version、Content revision、真实sourceVersion及Provider/schema generation保留。
- 真实身份与写权：准备实例由完整 release tuple、对象slice及受管 Provider/schema generation 唯一定位；规范化源闭包/公开对象集合摘要是该身份下不可变输入，相同身份不同摘要必须冲突，不能将摘要变化变成新实例绕过冲突。revision 不进入准备候选身份；客户端重试键只去重推进意图，不另立 release 身份。选择 Search 已有 Mongo typed slot 保存一份 authoritative preparation checkpoint、命令回执及流程执行 fence：访问以 exact identity 点查、单流程 CAS 和回执原子提交为主，无跨候选关系事务；闭包清单有界、可由 User immutable candidate 重建，证明保留覆盖回滚窗口，不以 Redis 临时缓存或 ES 唯一保存。完成证明是该流程的终态数据而不是第二 receipt registry；事务以 expected checkpoint version 和执行 token CAS 原子提交。SearchIndexView 候选投影是可重建的查询资源，不复制流程状态，跨 Mongo/ES 一致性遵循 [工程 DEC-032](../../runtime/system-architecture-and-engineering-guide/design.md#dec-032)。
- 状态、durability 与失败终态：准备需区分已受理/推进中、可显式恢复的受阻、已完成及不可恢复失败，具体闭集归对象契约。持久 checkpoint 至少能定位冻结输入、已验证投影范围和失败依据；Provider 实际可查询、闭包完整且证明随终态持久化后才算完成。进程死亡可留下推进中，显式续跑只有在有界执行租约失效并以 CAS 取得新 token 后才接管；旧执行者不得提交新 checkpoint/证明，同输入迟到 Provider 写仅按 source version/digest 幂等收敛。Provider 成功但 checkpoint 写失败时保留非 live candidate并从旧 checkpoint 重验，查询不偷偷修复或写入；身份/摘要冲突拒绝且不污染已完成实例，确定的无效源/闭包失败保持失败事实，需要新的合法源候选而非原位改输入。此对象只有派生准备进度，没有 active/latest、release 选择权或 rollback command，不构成第二 release 状态机。
- candidate 隔离：完整 release tuple `(environment, sourceOwner, releaseId, manifestDigest)` 与 canonical 对象身份共同确定 Creator candidate 文档，来源显式区分普通账户与 Creator；revision 只属于 pointer 世代，不属于 candidate 身份。Provider adapter 在同一部署 binding generation 内隔离新旧候选，外部公开 ID 不随物理键变化；同一 Creator 可在多个 tuple 并存，stage 不覆盖 live 文档。source version 来自 owner，同 candidate 的版本/摘要冲突按 DEC-002 原子拒绝；普通账户版本不与 Creator 候选版本竞争，同一公开身份的跨来源冲突阻断而非最后写入者获胜。物理键与过滤字段仍由后续 contracts/Provider adapter 定义，不另建业务身份 registry。
- 查询就绪与 CAS：证明必须绑定 exact release、Creator 源闭包、完整预期对象身份及投影摘要、唯一当前契约和受管Provider/schema generation，并证明实际查询可见；bulk 写成功或相同数量不足为证。Content 在自身正式 activation 边界验证当前目标的 Search 证明，所有调用入口均不得绕过；缺失、漂移、部分完成或当前依赖不可读即 fail closed。证明不新增可见性 authority，也不承诺跨库事务：CAS 前保持被验证 candidate 不变并禁止其 GC；并发 Provider 代际切换遵循 DEC-002 的受控部署串行边界，CAS 后不可达沿用跨域 ambiguous/readback 恢复而非伪称强事务完成。
- 读侧 fence：Search 每个相关请求通过 Content `ActiveReleaseFenceQueryPort` 的正式受信 transport 一次 pin 权威 tuple+revision，在 Provider 查询前施加 Creator 来源与 candidate 限制；result、suggest、retrieval、ids、计数、facet 与分页使用同一过滤，不做取回后丢弃的补救。普通账户来源保留原资格、隐私与鉴权，不受 candidate stage 覆盖。空 pointer 不暴露任何 release Creator；依赖错误不得猜旧 fence 或以缺失来源当普通账户放行。cursor 在既有查询、主体、策略及部署候选绑定之外绑定内容 tuple+revision；切换或回滚产生新 revision 后旧 cursor 失效，部署 candidate digest 不能替代内容 fence。
- 恢复、rollback 与保留：继承 [跨域 DEC-003](../../runtime/runtime-data-engineering/design.md#dec-003) 的环境发起、Content 唯一 CAS、unknown 先 readback、显式 rollback 与首次无 previous 语义。rollback 只选择保留且已验证的 previous tuple，通过新 revision 使其重新可读；不降低 external version 覆盖当前文档、不切换第二 Search active flag 或内容专属 live alias。旧 candidate 与媒体保留到活跃读引用和回滚窗口结束，显式回滚选择旧版本不是故障时在线 fallback；不更新 immutable producer bytes。
- 可表达性与证据边界：现役 `content/media/media_image_reprocess_run` 是持久准备同类：object 为 process_manager、operations 用 command/query facet，application 按命令摘要重放、store 用 Mongo transaction/CAS，HTTP handler 与 cmd bootstrap 已真实调用；metadata validator 的 commandOwnerKinds 明确接受 process_manager，projection command 禁令继续成立。SearchRequestFact 则只拥有追加查询事实和账号关闭死信恢复，不能借其 lifecycle_owner 承担可变候选准备。本裁决不需要通用 compiler/schema 新机制，但新对象尚未 authoring/编译，只有现役模式与校验源码的可行性证据，不是本能力 contract/runtime PASS。

## 5. 失败与恢复

- 失败类型：权限拒绝、依赖超时、版本冲突或持久化失败。
- 可见结果：调用方收到可区分的 canonical failure 或规格明确允许的降级结果；任何失败均不写入成功事实。
- 恢复动作：调用方按 canonical recovery action 重试、刷新或停止；不得自行合成成功结果。
- 禁止 fallback：不得回退到 Mock、旧 wire、双读双写或页面本地写副本。
