# L3 Story：趣信会话列表一致性 (`chat-list-ui-polish`)

> 所属能力：[`chat-experience-optimization`](../spec.md)

> Journey / Scenario：[`JNY-003 / SCN-008`](../../../spec.md#scn-008)

> 设计归属：[L2 DEC-001](../design.md#dec-001)

## 1. 用户价值

作为发起或接收消息的用户，
我希望`@我` 和 `未读` 的角标数量来自同一模型，并在阅读后按统一规则递减，
从而稳定完成会话、消息或通话协作。

## 2. 范围与非目标

### In Scope

- “趣信会话列表一致性”的输入、可观察主路径、失败语义以及与父能力的交接。

### Out of Scope

- 父能力中由其他 Story 独立拥有的行为、能力级架构决定和实现任务。

## 3. 行为要求

<a id="req-001"></a>
### REQ-001 趣信会话列表一致性

- `@我` 和 `未读` 的角标数量来自同一模型，并在阅读后按统一规则递减。

<a id="req-002"></a>
### REQ-002 用统一的 per-user inbox 数据模型承载列表展示与角标逻辑，避免页面本地推断造成的错数、假数、读后不减

- 用统一的 per-user inbox 数据模型承载列表展示与角标逻辑，避免页面本地推断造成的错数、假数、读后不减。
- `@我` 和 `未读` 的角标数量来自同一模型，并在阅读后按统一规则递减。
- 字号与摘要行一致或略小，不得抢标题视觉权重。
- 组合头像中所有子头像尺寸必须一致；不能出现上行/下行大小不一致的凌乱感。
- 对比度不能过强，不可脏、不可沉。
- 不得全屏满宽穿透头像区，需保持微信式 inset 视觉。
- 不得因为对比度过高而抢主信息层级。
- 显隐过程中内容区必须即时补位，不允许留下胶囊高度的白色留白。
- 角标只在服务端已读同步成功后递减。
- 列表行未读数、`未读` 胶囊数、`@我` 胶囊数必须来自同一用户级状态。

## 5. 验收场景

<a id="gwt-001"></a>
### GWT-001 趣信会话列表一致性

- GIVEN 发起或接收消息的用户具备有效身份，且父能力声明的输入与上游事实成立。
- WHEN 参与者执行“趣信会话列表一致性”对应的公开行为。
- THEN `@我` 和 `未读` 的角标数量来自同一模型，并在阅读后按统一规则递减。
- AND 失败时返回 canonical failure，且不产生伪成功事实。
