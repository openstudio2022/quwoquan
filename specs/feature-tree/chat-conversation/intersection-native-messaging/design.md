# L2 Design：交集原生消息 (`intersection-native-messaging`)

> 对应规格：[L2 spec](./spec.md)
>
> 设计触发原因：跨 chat-conversation、object-homepage-network、recommendation-platform、user-identity-profile-relationship 与 assistant-run-learning 五个领域的事实流动，且需要在消息域确立「不得引入垂类分支」这一长期约束。

## 1. 背景、目标与非目标

- 背景：消息域与交集域之间没有任何接口，联系首页的交集摘要由资料字段拼接伪装，会话页既无交集也无助手落地，打招呼不携带任何依据。
- 设计目标：在消息域建立一组垂类无关的交集消费接口，让交集事实的丰富度可以增长而消息域的结构保持不变。
- 非目标：不生产交集事实，不决定交集排序，不拥有 Gathering 的生命周期。

## 2. Story 协作与状态流

- 状态 owner：交集事实与行动提示由推荐域拥有，破冰依据由用户关系域随打招呼请求拥有，会话内的助手提及事件由消息域拥有。
- 并发边界：同一打招呼请求的依据只在服务端重解析成功时写入一次，重复提交不产生第二条依据。
- 幂等边界：同一条 @小趣 提及最多触发一次助手回复，重发消息不产生重复回复。
- 一致性窗口：交集事实相对推荐域最终一致，消息域展示的是读取时刻的快照，快照失效时降级为不展示而不是展示陈旧内容。

## 3. 端云与数据流

- App 责任：把交集引用作为意图上传，按云侧行动键与可达性渲染与分流，不做任何句子拼接与垂类判断。
- Metadata/contract：行动键闭集、路由类别闭集与目标可达性只在推荐域 registry 与其投影中定义，消息域只引用。
- Service/Data/Ops 责任：用户关系域负责按当前发起方重解析交集引用后写入依据，助手域负责基于注入的上下文生成带引用边界的回复。
- 缓存或投影：联系首页的交集聚合是读取时投影，可整体重算，不作为写入事实保存。
- 外部依赖：无。

## 4. 关键决策

<a id="dec-001"></a>
### DEC-001 消息域只消费云侧行动契约，不建立第二套行动语义

- 决策：消息域内所有交集行动一律通过云侧登记的行动键、路由类别与目标可达性驱动，端侧不维护行动到页面的第二张映射表。
- 理由：行动键闭集已经是推荐域 registry 的一部分并已有 codegen 产物。端侧再建一张映射表会让「新增行动」需要两处改动，而两处的漂移在运行时表现为无承接页的死入口。
- 被否决方案：端侧按交集类型硬编码行动分支——垂类扩展时必然要改端，与垂类扩展契约直接冲突。
- 影响 Story：[`actionable-object-card`](./actionable-object-card/spec.md)、[`conversation-intersection-header`](./conversation-intersection-header/spec.md)
- 关联要求：`REQ-002`、`REQ-005`
- 关联验收：`SIT-002`、`SIT-003`

<a id="dec-002"></a>
### DEC-002 破冰依据以服务端重解析结果为准，端侧传入只作为意图

- 决策：打招呼携带的交集引用被视为发起方声明的意图，服务端按当前发起方与接收方重新解析该交集是否成立，成立才写入依据。
- 理由：交集是两个主体之间的关系事实，随时间与授权变化。若直接采信端侧内容，任何人都可以声明一条不存在的交集作为破冰理由，而接收方看到的「为什么是你」将不可信。
- 被否决方案：信任端侧传入并在展示时标注来源——不可信的内容加标注仍然不可信，且接收方无从判断。
- 影响 Story：[`greeting-intersection-context`](./greeting-intersection-context/spec.md)
- 关联要求：`REQ-004`
- 关联验收：`SIT-001`

<a id="dec-003"></a>
### DEC-003 交集只进入主体明确的界面，消息首页保持未读心智

- 决策：交集只出现在联系首页与 1v1 会话头部，消息首页不叠加交集行，群会话头部不展示交集。
- 理由：交集是「我和某一个人的共同点」，主体必须唯一才有意义。群会话的对端不是单一主体，消息首页的心智是未读会话队列，在其上叠加推荐内容会把推荐插进消息主路径并稀释未读信号。
- 被否决方案：在消息首页每行补一句交集——会话行的信息预算已被最后一条消息与未读占满，交集在此处只能被压缩成聚合计数，而聚合计数不构成理由。
- 影响 Story：[`contact-home-intersection-facts`](./contact-home-intersection-facts/spec.md)、[`conversation-intersection-header`](./conversation-intersection-header/spec.md)
- 关联要求：`REQ-003`
- 关联验收：`SIT-001`

<a id="dec-004"></a>
### DEC-004 分享进会话的可行动主体是对象，不是交集

- 决策：会话内可转发主体扩展到 Gathering，但不扩展到交集本身。
- 理由：把「我和某人的交集」分享给第三方在隐私上说不通，因为该事实的另一半主体没有授权。真正有分享价值的是交集所指向的目标对象。
- 被否决方案：允许转发交集卡并在转发时脱敏——脱敏后的交集卡失去主体，也就失去全部信息量。
- 影响 Story：[`actionable-object-card`](./actionable-object-card/spec.md)
- 关联要求：`REQ-005`
- 关联验收：`SIT-002`

## 5. 失败与恢复

- 失败：交集引用重解析不成立、行动目标不可达、助手不可用、交集聚合读取失败。
- 检测：服务端重解析返回不成立，可达性标记为不可承接，助手域返回结构化不可用，聚合读取返回 canonical failure。
- 可见结果：不展示依据而不是展示空依据，行动展示为不可执行而不是可点击，助手给出结构化不可用而不是无依据回复。
- 恢复：打招呼在无依据时仍可作为普通问候完成，行动在目标就绪后自动转为可执行，助手可重试提问。
- 禁止 fallback：不得以资料字段拼接冒充交集，不得以聚合计数代替具体交集点，不得在无承接页时仍渲染行动入口。

## 6. 质量与观测

- 隐私：交集依据只在双方之间可见，不进入推送载荷，不随对象分享外流给第三方。
- 指标：破冰依据的展示与重解析拒绝分别可观测，行动 card 的可执行与不可执行分流比例可按 vertical 统计。
- 归因：交集引用与 referralSource 贯穿破冰到行动的全链路，以支持按 vertical 的转化统计。
- kill-switch：交集在消息域的展示可整体关闭，关闭后退化为不展示而不是展示占位。

## 7. 迁移与回滚

- 切换顺序：先让联系首页的交集摘要从资料拼接切换为真实聚合，再接入破冰依据与会话头部，最后接入可行动 card 与助手提及。
- 数据处理：交集聚合为读取时投影，回滚时无数据迁移。
- 删除的实现：资料字段拼接的伪装摘要与拼接裸标识的行在真实聚合落地时删除，不保留为降级路径。
- 回滚条件：出现未经重解析的依据写入或出现按垂类命名的端侧分支时立即回滚该步骤。
